# 网格交易管理

把 `26年网格记录.xlsx` 里「交易记录」这张手工表，变成一套**能自动生成待买 / 待卖清单、能算奖励、能自证数据没错**的本地网页工具。

规则口径全部来自 `网格交易管理·规则确认与开发规划 V1.1`（D1–D7 / R1–R7 / P1–P12），本文只记录「文档 → 代码」的落点，以及两处必须说清的偏差。

## 与文档的对照

| 文档 | 落点 |
| --- | --- |
| D1 目标售价 = 成交价 | `domain/ledger.ts`：`priceCents = E`，`priceSource='target'` |
| D2 33 笔历史卖出不生成待买 | `rebuyStatus='repaid'`，只有 P 列非空才建 `RebuyOrder` |
| D3 P 列为空是唯一判据 | `ledger.ts` 里 `r.earlyBuyPriceCents !== null` |
| D4 允许先卖后买 | `sellBeforeBuy` 标记；**不进异常清单**（异常清单只有缺价 / 缺日期 / 负盈利三类） |
| D5 待买按 P 列生成 | `rebuyPriceCents = P`，无批次时成本也取 P |
| D6 E 列 = 待卖清单 | 每笔有剩余持仓的批次生成 1 个 `SellTarget` |
| D7 只读「交易记录」 | `io/parseWorkbook.ts` 固定取 `SheetNames[0]`，其余 5 表不读 |
| R4/R5 组池与 FIFO | `ledger.ts` 的 `computeGroups()`：全部真实卖出入池 → 按 `(stockId, 成本价)` 分组 → 手数 = floor(组池 / (价×100)) → FIFO 挂给 open 订单 |
| R7 数量守恒 | `ledger.ts` 的 `checks[]`，概览页每次重算都跑 |
| §7.2 精度 | `domain/money.ts`：整数分，`toCents` 走字符串通道，禁止浮点参与判定 |
| §8.4 涨跌停 | `domain/limit.ts`：`round(昨收 × (1±pct), 2)`，`unknown` / 缺昨收 → 返回 null，不出建议 |
| P10 编辑审计 | `store/useApp.tsx` 的 `editRecord`：逐字段 diff → `auditLogs` 落库，明细行「历史」可查 |
| P9 导入幂等 | `importKey` 在导入时生成后**永不改写**，所以改过的行重复导入不会被覆盖 |

## 8 个基准数字（真实文件 dry-run 结果）

| 指标 | 结果 |
| --- | --- |
| 有效行 | 62 |
| 买入 | 31,800 股 / ¥360,320.00 |
| 卖出 | 33 笔 / 18,600 股 / ¥190,558.00 |
| 实现盈利 | ¥9,830.00（32 笔，未扣费用） |
| 待卖 | 29 条 / 15,200 股 / ¥202,284.00（预期收益 ¥12,515.00） |
| 待买 | 4 条 / 2,100 股（含奖励 100 股）/ ¥16,601.00 |
| 净持仓 | 13,200 = 15,200 − 2,000 |

### 偏差一：卖出金额 / 盈利各差 ¥1

文档写 ¥190,559 / ¥9,831，本实现是 ¥190,558 / ¥9,830。
原因只有一条：**安道麦那一行的 E 列是 6.331（三位小数）**。文档用浮点直接乘股数得 6,331.00；本实现按 §7.2「价格一律整数分」把 6.331 归到 6.33，于是金额少 1 分、盈利少 ¥1。
基准校验对这两项给了 ±¥1 容差并在界面上标注，其余 14 项都是硬相等。

### 偏差二：R44 的成交价（有一个开关）

R44（三一重工 18.81 / 300 股 / 已全卖）的 E 列**有公式、没有缓存值**。文档说它「目标售价为空 → 盈利无法计算，不入组池」，但文件里的公式其实能算出 18.81 + 1.07 = 19.88。

- **默认（关）**：已成交行不推定成交价 → R44 进「待补价格」，全表盈利 ¥9,830 = 文档口径。
- **打开**：`已成交行也按「买入价+间隔」推定成交价`（导入页 / 备份页的勾选框）→ 盈利变 ¥10,152。

代码里就是 `buildLedger(..., { deriveSellPrice })` 这个参数，没有藏逻辑。

**两条设计取舍**：

1. 批次剩余、待卖清单、待买单、组池奖励全部是**每次重算的派生数据，不落库**。
   落库的只有原始行、股票配置、导入批次、审计日志。这样不可能出现「库里存的和算出来的不一致」。
2. **UI 全部走 `animal-island-ui`**（Card / Button / Tabs / Tag / Input / Select / Drawer / Modal /
   Switch / Upload / Collapse / Calendar / Notification），只有价格网格用原生 `<table>`——它是个二维矩阵，
   不是数据表格，用 Table 反而更绕。配色、圆角、字体全部继承库的 `--animal-*` token。

## V9 做了什么（跨数据跳转 + 可叠加筛选）

**URL 承载筛选（S7）**：5 个 tab 改由 hash 路由驱动，明细筛选条件全写在地址栏里，
例如 `#/trades?stock=柳工&status=pending,sellDateMissing&from=2026-02-01&to=2026-02-28&row=63`。
深链可直达、浏览器前进后退可用；明细页内改筛选用 replaceState 同步，不产生历史垃圾。

**跨数据跳转 + 筛选联动**——跳过去之后筛选条件真的生效，不是只切页面：

| 从哪里点 | 跳到哪里 | 带什么筛选 |
| --- | --- | --- |
| 概览「待补日期 N 笔」标签、日历「N 笔缺日期」 | 明细 | 状态 = 缺卖出日期 |
| 导入 · 异常清单某一行 | 明细 | 行号 = 该行（+股票） |
| 统计 · 月度成交的某个月 | 明细 | 日期区间 = 该月起止（「未填日期」→ 缺卖出日期） |
| 统计 · 成交日历「看这天明细」 | 明细 | 日期区间 = 那一天 |
| 统计 · 按股票的某只票 | 明细 | 股票 = 该只 |
| 统计 · 组池的某个价组 | 明细 | 股票 + 价格 = 该回补价 |
| 挂单 · 待买/待卖/今日挂单条目（整行可点） | 明细 | 行号 = 该条来源行 |
| 概览 · 价格网格某一行、敞口标签 | 明细 | 股票 + 价格档 / 状态 = 空头敞口 |

**筛选可叠加**：状态从单选下拉改成多选 chips
（有剩余 / 已卖完 / 待回补 / 空头敞口 / 缺买入日期 / 缺卖出日期 / 缺价格），多个状态取交集，
与股票、日期区间、价格、关键词、行号之间也是「与」；每个已生效条件显示成一颗可点掉的 chip。

**一键复位**：「清空筛选」按钮把股票 / 状态 / 日期 / 价格 / 关键词 / 行号一次全清
（排序与「显示已删除」开关不动），有任何条件生效时才出现在筛选区。

**恢复前强制导出（S4）**：从 JSON 恢复是整库覆盖——现在点恢复时先把当前数据自动导出一份
`grid-backup-before-restore-*.json` 快照再写入，导出失败则整个恢复中止。
快照也算一次备份，会刷新「上次备份」时间（即使随后的恢复失败）。

**网格口径**：价格网格与一切「网格」规划只使用每只股票配置的**绝对间隔值**（`intervalCents`）
派生价格档，不引入任何百分比范围——原规划「网格范围上下留 5%（P12）」已取消。

## 视觉分层：表头不再和数据糊在一起

三个通用类（都在 `src/styles.css` 末尾），全局复用：

| 类 | 用途 | 效果 |
| --- | --- | --- |
| `.sec-head` | 卡片内的小节标题（今日挂单 / 月度成交 / 按股票 / 导入批次…） | 标题下一条实线（`--line-strong`），线以上是标题、以下是数据 |
| `.data-block` | 列表容器（待买 / 待卖 / 可挂买 / 可挂卖 / 异常清单 / 批次） | 1px 边框 + 圆角 + 半透明白底，行间用 `--line` 分隔 |
| `.table-wrap` | 价格网格 | 整表套边框圆角；表头单独给底色 + 下边线，数据行隔行浅底 |

配套细节：

- 分隔线分三档 `--line` / `--line-strong` / `--line-soft`，行间用最浅那档，区块和表头用深一档，视觉上才有层次。
- 吸顶块底边加了一道发丝线（`.page-sticky::after`），滚动时和下方内容分开。
- 行内操作多的时候（买 8.01 × 500 + 计划 + 记成交）会挤成两行叠字，
  改用 `.line.wrap-row`：金额留在右上，按钮整行下移。
- 指标条金额太长会贴在一起：`.metric-strip.two-col` 在手机上排成 2×2。

E2E 里有断言守这两件事，`npm run e2e` 会检查：
表头有底色且与数据行不同、表头有下边线、表格在带边框的容器里、挂单页有 ≥2 个带边框数据块且分组标签存在。

## 口径修正：守恒式为什么用「待补敞口」

文档 §R7 式 2 写的是「Σ待卖量 − Σ待买基础量 = 净持仓」。这条等式只在**待买全部来自无买入批次的卖出**时成立。
一旦你给一笔「从批次里卖出」的记录补了 P 列（这是很自然的操作：卖了想在同一价位接回来），
系统会同时多出一个待买和一份待卖，等式就歪了——因为它把「买入意愿」和「空头欠账」算成了同一个数。

所以 V2 把待买分成两类，守恒式改成：

```
Σ待卖量 − 待补敞口 = 净持仓        // 待补敞口 = 只有无买入批次的卖出
```

26 年这份数据里所有 P 列卖出都没有批次，所以两种写法算出来完全一样（15,200 − 2,000 = 13,200），
文档的基准数字不受影响；但你自己补录数据时不会再莫名其妙红灯。

## 部署

```bash
npm run build          # 产物在 dist/，纯静态，无后端
npx serve dist         # 或扔进 Nginx / OSS / GitHub Pages
```

- **子路径部署**要改 `vite.config.ts` 的 `base: '/repo/'`，否则资源 404。
- 数据在浏览器 IndexedDB 里，**换设备/换浏览器看不到**：用「管理 · 备份」导出 JSON 再导入。
- Safari 长期不访问会清理站点数据，所以概览页有「N 天没备份」的提醒。
- 字体是最大的产物（Noto Sans SC 三档），公网部署建议按需子集化或改系统字体。

## 数据与隐私

数据只存在浏览器 IndexedDB（Dexie），没有任何网络请求。长期不打开会被 Safari 清理，**建议每周到「备份」页导一次 JSON**。`tests/fixtures/` 和 `public/demo/` 里是这份 26 年记录的原文件副本，如果这个仓库要外发，记得先删掉。
