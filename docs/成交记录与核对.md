# 成交记录与核对

更新：2026-10-29。这里说明当前已实现的记账流程；后续扩展方案见《记账流程与防重改进建议》。既有盈利、欠股、奖励及回本链口径保持不变。

## 一笔真实成交只保存一次

先核对实际发生的股票、方向、日期、价格和股数。已经录入的成交从 **管理 → 成交流水** 查找；确认尚未记录时再保存。

| 情况 | 操作 |
| --- | --- |
| 买入一批新的独立库存 | 明细 → 新增买入，填写真实成交信息 |
| 买回一笔欠股 | 对应待买档 → 记成交，核对基础回补、所含奖励和剩余欠股 |
| 多个同价来源合并成交 | 挂单 → 记成交，核对本次每个来源贡献；只成交部分就填本次实际量 |
| 原先的裸卖行需要补齐同行买入 | 先查流水，确认买回尚未另记，再补买入；已有回补成交或人工高位关联时继续走回补入口 |
| 相同股票、方向、日期、价格和数量已经存在 | 对照提示的成交编号；已记过就查看原成交，确为另一笔才勾选确认 |
| 从文件增量更新历史记录 | 优先精确匹配；有多个候选、已删除历史或裸卖身份不明确时，逐行选择更新来源、跳过或确认新增 |
| 已记回补，又从文件导入同一买回 | 预览进入待选择；若是同一笔就跳过，不能再新增库存 |

同一买回既抵减欠股又形成库存，是同一成交的两个结果。例如欠500股、实际买回200股、奖励0股，保存后新增库存200股、基础欠股剩300股。不要再独立新增另一笔200股。

## 保存前核对什么

成交表单显示本次实际价量与金额。合并成交另列各来源本次贡献；回补表单显示基础欠股的前后变化，奖励包含在本次总买入量中。买回尚未卖出，不增加后续回本盈利；计划回补节省也不计盈利。

明细卡把 **实际买入、实际卖出、计划卖价、计划回补** 分开命名。没有真实买入时显示“尚未买回”，已有独立回补时从回补流水查实际买回，P列不会冒充实际买入价。

## 防重的三层保护

1. **重复点击和重试**：一次草稿使用固定操作编号；同编号同内容返回原回执，同编号不同内容报冲突。成功之后的新成交使用新编号。保存中按钮禁用只是辅助保护。
2. **来源凭据**：可填写“券商/日期/成交编号”等具有明确唯一范围的凭据号；同凭据不会再次保存。委托号可能对应多次成交，应使用每次真实成交自己的编号。凭据号相同但方向、股票、日期或价量不同会要求核对。
3. **相似事实**：同股、同方向、同日、同价、同量只提示疑似重复。核实是两笔真实成交时允许保留，不自动删除或合并。普通导入会检查已有买卖及回补事实。

新增主键在写事务内分配，新增使用唯一约束；成交、来源分配、初次归链、回执和相关审计在同一事务提交。保存时重读当前库存与欠量，不以旧页面余额放行。返回原回执时不会重复扣库存或奖励。

## 成交流水怎么读

管理 → 成交流水支持搜索股票、日期、成交编号和凭据号，并可只看待核对。

- 普通买入、卖出、回补都属于真实事实；历史同行买卖按两个方向列出。
- 一笔合并成交只有一条回执，下方列出记录或回补分配，不将生成的库存再算一次买入。
- 高位成本分配、链分支不是新成交。日历和价格树同样不重复增加合成卖出的数量和次数；相关盈亏仍保留。
- “已记账待核对”表示已落库，尚未与凭据核验；“已与凭据核对”不表示已卖完、欠股清零或链已回本。
- 原始价量或日期变化后，已核对状态自动失效，流水显示现有事实，需要重新核验。

老记录仍可查看并核对；系统不会根据相同价量自动替历史成交猜测分组。费用没有纳入这些按价量计算的金额，不能把它当作券商可用现金。

## 撤销与依赖

新回执可在成交流水选择“撤销整笔”。确认信息列出分配数量及后续卖出/历史引用、后续回补数量；提交时再次检查依赖。合并成交不能在某个来源行只删除或撤销一份。

若已有后续成交，先核对并处理后续成交。回补批次有软删除卖出历史时也会阻止删除来源，避免留下悬空引用。没有依赖时，整笔撤销原子恢复来源额度，清理被撤销回补的附属拆卖档并保留撤销回执。整笔撤销的分配不能单行恢复。

历史同行买卖同时承载两个方向，暂不支持从单方向回执一键撤销；在明细核对更正，避免误删另一方向。已存在但无法自动覆盖欠股的买回，暂不提供任意改挂到另一笔卖出的操作，应核对日期、价格与原始来源，不能通过重复记成交来修正归属。

## 导入与备份

普通导入显示“新增 / 更新 / 无变化或跳过 / 待选择”的实际写入计划。文件本身的台账预演与写入当前台账的变更分别解释；仍有待选择行时不能提交。提交重新读取当前数据库并验证选择，不能把预览时的模糊候选直接套上。

JSON结构版本12与完整台账Excel保存成交回执、凭据号、核对与撤销状态；兼容旧完整Excel没有“成交回执”表的文件。旧版程序不认识结构12时应使用新版本恢复。

缺交易记录表的JSON拒绝恢复；重复主键、非法主要金额/股数、循环来源和悬空回执会拒绝。旧格式的可缺省表仍按兼容规则处理，因此仍应使用程序完整导出的文件，不把部分JSON当作局部合并工具。
