### 1.3 一次可复查的验收记录应包含什么

记录应用提交号、输入文件或最小交易表、股票配置、计算设置、人工关系、计划、成交日期/时刻和操作顺序。操作前后分别保存原始表与派生结果，至少核对：记录数、永久 ID、真实买卖股数、批次剩余、待卖、待买基础股/奖励股/来源档、敞口、总盈利、链归属与审计。页面验收另记录当前选股、区间、沙盒状态、弹窗实际采用的默认值与浏览器控制台错误。

同名股票、同价、同一天都不足以证明是同一笔交易；反过来，页面行合并也不应消灭底层来源身份。

## 2. 必须分开的五类数字

| 数字 | 口径 | 最常见的误读 |
| --- | --- | --- |
| 实际持仓/净股数 | 真实买入及回补买入减真实卖出；虚拟回补批次只代表已发生的买入 | 把回补批次又作为原始买入加一遍；把高位合成卖出当第二次实盘卖出 |
| 待卖与敞口 | 批次剩余对应待卖；无库存交割的未补卖出对应敞口 | 全额挂高位后仍把同一份交割记敞口；缺目标价时误以为库存不存在 |
| 待买建议 | 欠股回补与可选再买分开；基础股、奖励股分别核对 | 把下一轮“可以买”误认为必须补的欠股，或把奖励当基础回补 |
| 总账盈利 | 实际卖出成本差；当前规定的高位挂钩暂记亏损也计入；未知成本不捏造盈利 | 同一根卖出及高位合成视角重复计盈利或交易量 |
| 回本链盈亏 | 原始亏损＋已归属后续库存的已实现净盈利，可正可负 | 买回未卖便算盈利；回补节省加进回本；自动归属在后续亏损或换轮时丢失 |

计划只改变建议展示、区间、导出和成交默认值，不改变真实库存、成交盈亏或原始记录。实际成交保存后，才以实际价量改变账本。

## 4. 五个完整算例

### 算例一：部分卖出，P列可选再买与原持仓并存

配置T间隔2元。第1笔5元买500，目标7元；随后按7元卖200，P填5元，买入日早于卖出日。

| 核对项 | 计算 | 结果 |
| --- | --- | --- |
| 原始买入量/金额 | 500 / 5×500 | 500股 / 2500元 |
| 真实卖出量/金额 | 200 / 7×200 | 200股 / 1400元 |
| 已实现盈利 | (7−5)×200 | +400元 |
| 剩余及待卖 | 500−200 | 300股@7 |
| 待卖预期盈利 | (7−5)×300 | 600元，尚未实现 |
| P列再买 | 已卖200、非先卖后买 | 200股@5，锦上添花 |
| 敞口/净持仓 | 0 / 500−200 | 0 / 300股 |
| 奖励 | 利润400小于5元一手500元 | 0股 |

这里的钱一部分已通过卖出回到现金，一部分仍在300股库存里。P列可选再买不会把持仓300改成500，也不能让200股变成“应该买入”的欠股。若另有真正先卖后买200@5，两者最终价相同仍要分组；基线此交叉场景存在 O02。

### 算例二：同一笔先卖，多种回补渠道只扣一次

无历史高位交割；7元先卖500。该行后来5元买100；另有独立5元真实买300；按该根成交回补基础100。所有买回日期已知且在根卖出之后，没有奖励。

| 覆盖输入/结果 | 数量 |
| --- | --- |
| 卖出 `sellQty` | 500 |
| 本行买回 `ownLotCoverQty` | 100 |
| 本行后尚欠 `owed=500−100` | 400 |
| 独立真实回补 `realCoverQty` | 300 |
| 待买计划基数 `baseQty=400−300` | 100 |
| 已成交基础回补 `execBaseQty` | 100 |
| 还欠基础股 `openBaseQty=max(0,100−100)` | 0 |
| 实际买入库存 | 本行100＋独立300＋成交虚拟100＝500 |
| 守恒扣回 `deductQty` | min(100＋300＋100,500)＝500 |
| 真实净股数 | 500买−500卖＝0 |
| 待卖−敞口−守恒扣回 | 500−0−500＝0 |

虚拟100股已经由执行成交扣欠量，不能再被“同价真实覆盖”加一遍；否则会把其它欠股错误盖掉。净股数0不表示页面没有待卖库存：这套台账同时保留买回库存和先卖交割的对应扣减，因此必须看完整守恒式，不能只用“待卖等于净股数”判断。

### 算例三：回本链的盈利、亏损和第二轮不能丢

原始高位10元500，7元亏损交割，原始亏损−1500。第一轮实际5元回补500，再7元卖500；第二轮5元回补500，再8元卖500。以下为应有归属：

| 时点 | 原始亏损 | 后续已实现净盈利 | 链累计 | 链当前持仓 |
| --- | --- | --- | --- | --- |
| 高位卖出后 | −1500 | 0 | −1500 | 0 |
| 第一轮5元买回、未卖 | −1500 | 0 | −1500 | 500 |
| 第一轮7元卖完 | −1500 | +1000 | −500 | 0 |
| 第二轮5元买回、未卖 | −1500 | +1000 | −500 | 500 |
| 第二轮8元卖完 | −1500 | +2500 | +1000 | 0 |

全局真实总买1500股、总卖1500股、净0，实际总盈利也为−1500＋1000＋1500＝+1000。回补节省不加进后续盈利。**C02实际漏了第二轮归属**：第二轮买后链持仓0，卖完链后续仍1000、累计仍−500，而全局已+1000。

另从第一轮“独立真实5元买500自动归槽”分叉：改成4元卖300，应为后续−300、链累计−1800、剩200；**C01实际把该低位批次改建独立亏损锚点**，原链后续及库存都消失。这证明“任意卖价累计”必须同时覆盖负利润，不能只测6/7/8元的盈利卖出。

### 算例四：改量后来源贡献必须守恒

根欠1000，拆4元200＋默认5元800。两个来源各改单至最终5元、各只建议100，最终同目的同价合并为200。

| 项目 | 4元来源档 | 默认5元来源档 | 合计 |
| --- | --- | --- | --- |
| 实时容量 | 200 | 800 | 1000 |
| 本次计划贡献 | 100 | 100 | 200 |
| 成交200应分配 | 100 | 100 | 200 |
| 成交后应余 | 100 | 700 | 800 |
| 基线实际扣减（O04） | 200 | 0 | 200 |
| 基线实际余量 | 0 | 800 | 800 |

两种结果总余量都800，库存守恒都可能通过；只有“按来源计划贡献执行”能发现扣错档。建议量、容量、计划贡献是三个不同概念：不能让建议200携带未截断的来源200＋800，再由保存按列表先后随意分走。

跨目的的来源即使都最终5元，也不能做上表这种合并；欠股与可选分别出行。两成员总改单1股时，贡献必须精确1＋0或明确拒绝，不能强制1＋1而保存2股（O05）。

### 算例五：奖励数量合法，实际金额仍可能超预算

5元买500、7元卖500、P5，实际盈利1000。按5元一手500元，组池可授2手即200奖励股；基础回补500，建议总700。

| 成交情况 | 基础股 | 奖励股 | 奖励实际花费 | 可用利润 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 5元成交700 | 500 | 200 | 5×200＝1000 | 1000 | 数量与金额都覆盖 |
| 10元成交700 | 500 | 200 | 10×200＝2000 | 1000 | 奖励资金差1000；不能仅看200股额度合法 |
| 10元按利润重新算整手 | 依真实欠量 | 100 | 10×100＝1000 | 1000 | 仅说明预算可支持100奖励股，不自动改写已发生成交 |

基线 O03 允许第二行保存，事后才亮预算检查。如果用户是在忠实补录既成事实，不能简单抹掉或拒绝事实；可以要求明确“超出利润使用自有资金”。若是实时策略建议，则应按实际价重新计算预算，且同组多来源在一个事务内累计支出。两种用途需分别定义。

## 5. 核心核对式：数量、归属、来源与金额各有防线

### 5.1 金额与股数的输入不变量

价格以整数分、股数以整数股处理。有效值还必须满足 `Number.isFinite`、`Number.isSafeInteger` 和业务范围；两个安全整数相乘后仍要检查乘积安全。四舍五入后的分不能是 `NaN`、`Infinity` 或非安全整数；未知值用明确的空值表达，不能用0掩盖缺失。

内部“分”避免常见小数比较误差，但不自动解决大数溢出。V05 说明仅靠“整数分”或 `Number.isInteger` 不足以保证数值安全。

### 5.2 数量守恒

```text
净持仓 = Σ真实买入批次股数（含回补成交生成批次） − Σ真实卖出股数
Σ待卖档数量 = Σ可售批次剩余数量       # 缺目标价须另显异常，不能假装没有库存
Σ待卖量 − 待补敞口 − 空头回补基础扣回 = 净持仓
```

高位挂钩的合成卖出是同一交割的成本视角，不能再进真实卖出股数/金额/次数。暂记亏损按现行总账规则单独纳入，不能因此把量也重复。

单根覆盖计算的非负数均应先限制在合法整数范围：

```text
own       = min(本行确认买回, 卖出量)
owed      = 卖出量 − own
real      = min(独立真实覆盖, owed)       # 不包含执行生成的虚拟批次
base      = max(0, owed − real)
openBase  = max(0, base − 已成交基础股)
exposure  = max(0, owed − real − 已成交基础股 − 高位交割股)  # 仅符合敞口条件的卖出，否则为0
deduct    = min(own + real + 已成交基础股, max(0, 卖出量 − 高位交割股))  # 同样仅符合敞口条件时计，否则为0
```

奖励股是额外实际买入，不是基础平欠，不能把奖励也减敞口。已经高位交割的份额不会在永久了结后复活为另一份待卖库存。

### 5.3 归属守恒：现有数量检查没有覆盖的部分

```text
对每批库存：Σ各链拥有的份额 + 未归属份额 = 该批实际股数
对每次卖出：Σ各链消耗的份额 + 未归属消耗 = 该笔实际卖出量
对每份归属：后续盈亏 = (实际卖价 − 实际成本) × 实际消耗的归属股数
链累计 = 原始亏损 + Σ归属后续已实现净盈利
链持仓 = Σ尚未被卖出消耗的归属份额
```

同一份额不能跨两链整笔复制；已归属库存不因后来亏损被提升成新锚点而失去原归属。卖出→回补→再卖的任意代数都要沿来源传递。结束后已拥有的库存仍更新旧链；新库存是否进入由明确结束边界判断。

**C01、C02可以在所有现有数量checks绿色时发生**：总账没有多买少卖，但链的归属、持仓、进度和待买覆盖变错。需要新增归属守恒，不能只增加页面提示。

### 5.4 建议与计划贡献守恒

```text
每行建议量 = Σ本行各来源的本次贡献量
0 ≤ 本次来源贡献 ≤ 来源实时容量
Σ同一来源在各建议的贡献 ≤ 来源实时容量
Σ合并成员保存的计划量 = 用户输入的合并计划量
同一建议的所有来源必须同股票、同业务目的
```

容量可大于贡献，贡献不可偷偷等于容量。修改建议不改变原始成交/库存；按实际保存时，事务内仍须重读账本核对容量，防止过期界面重复执行。

### 5.5 奖励资金与导出引用守恒

```text
奖励实际支出 = Σ(每笔实际奖励股数 × 该笔实际成交分价)
同价组可用利润 − 历史奖励实际支出 − 本事务拟新增奖励实际支出 ≥ 0  # 受策略预算限制的成交
```

若允许超预算事实录入，需要显式资金来源与缺口，不能把超支描述成已满足策略。不同股票、不同成本组、旧历史价组不能混用额度。

任一成功操作后的全量快照还应满足：永久主键唯一、每个真实/虚拟引用有源、父子图无环、每个已消费下一轮来源可追溯、软删除历史具有可解释的恢复路径。**成功导出自己的备份再恢复必须成立**；D03–D05表明“当前界面能算”不等于“快照可恢复”。

## 6. 可重复执行的验收顺序

1. 先存合法原始快照，使用独立临时库；记录基线提交、股票配置、计算设置。不要用正在使用的唯一台账做破坏性验收。
2. 运行领域与IO测试、lint、生产构建；这些通过后按上表补交叉反例，尤其是自动归属×亏损、多轮、同日结束，以及选股×计划×拆档×奖励。
3. 运行真实 IndexedDB 记账流程与移动端冒烟。页面操作之后读实际库及派生结果，不只看成功提示。
4. 每条成功动作后导出JSON、完整Excel；在隔离空库恢复、再重复恢复；比对原始表与核对快照。对非法输入检查拒绝前后原库不变。
5. 最后做升级、离线、多标签和中断故障专项；分别记录已执行环境、可恢复范围与仍未覆盖项。

## 7. 修复后的最小回归门槛
