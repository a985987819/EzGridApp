# 三类交易生命周期与完成口径（Agent 必读）

> 本篇是当前**唯一**按「一笔数量如何拆成多次完成」来讲交易生命周期的文档。
> 想查字段/类型速查看 `docs/detail-kinds.md`；操作步骤看 `docs/使用手册.md`；历史决策看 `AGENTS.md`。
> 文中所有状态都指**派生结果**（每次从 records / executions / hedges / extraTargets / chainLinks 重算，绝不落库）；
> 金额一律整数分，价格判定走 `domain/money.ts`，计划价只影响展示。

## 0. 总览：只有三种业务，共用一套完成判定

**完成状态是派生量，不是存进数据库的一个标记**。界面上的「已完成 / ✅ / 已回补完 / 已不亏钱 / 隐藏已完成」，都是领域函数按当前成交份额重算的结果；撤销、软删、改子单、恢复备份后必须重算，不能缓存旧结论。

| 情况 | 起点 | 过程中间态 | 完成条件 | 完成后钱去哪 |
| --- | --- | --- | --- | --- |
| ① 正常买单 | 买入批次 `Lot`（C 列买入价 + 份额） | 待卖 `SellTarget` = 剩余 × 目标价（E 列，缺则买入价+间隔）；可拆档、可改单（只展示） | 实际卖出累计 = 买入数量（按 `soldLotId` / 来源份额扣减，`remainingQty === 0`） | 已实现盈利进总账与组池；可再买下一轮 |
| ② 回本链 | 高位 a 买、低位 b 卖产生亏损种子（含挂钩了结） | 更低价 c 买回（自动价位槽 / 人工归属）→ 在 b 再卖，逐次累加已实现净盈利 | **链**完成 = `netCents = lossCents + profitCents >= 0`；子轮次的卖出次数只记在 `cycles`，不是完成条件（见 §2.3） | 后续盈利归原链；回补节省只展示不计入；不重复进奖励池 |
| ③ 底仓做T | 从回本链**单向**切入（显式 `baseT`） | 卖出订单数量拆成多笔子单逐步买回（`BaseTChildModal` / `recordRebuy(date?)`） | 全部卖出数量买回：`boughtQty === sell.qty && remainingQty === 0`；每笔成交各算一段价差 | 只计本次做T盈利并在卖出日进日历；不建/不修回本链 |

**三条铁律**（改动前必读，违反就会出现「界面已完成、账上还没完成」）：

1. **完成只看实际成交份额，不看计划、不看标签。** 合并 / 拆档 / 改单 / 区间筛选 / hideDone 都只改显示。
2. **一份数量只能扣一次。** 真实买入覆盖、回补成交基础股、挂钩了结份额、奖励股各走各的减法；
   统一在 `domain/cover.ts`（`owed → baseQty → openBaseQty → openExposureQty`）和 `domain/booking.ts` 回执分配里完成。
3. **一笔拆多次时，每次成交只消耗剩余额度；剩余归零才翻转状态。** 撤销 / 删除必须在事务内重读额度，
   有后续成交或历史引用时先拦，不能靠猜顺序补账。

## 1. 情况① 正常买单：按间隔挂卖，卖完即完成

### 1.1 批次与待卖如何派生

`src/domain/ledger.ts:85-155`：排除 `deletedAt` 后，用 `buyQtyRaw / deriveBuyQty` 建 `lot:<行>`；`targetPriceCents` 取 E 列，缺值时按「买入价 + 该股 interval」推导（已成交那截的 `sell.priceCents` 仍保持 null，不伪造成交价，V9.80）。`486-550`：对 `remainingQty > 0` 的批次生成 `SellTarget`——`extraTargets` 按 `at` 先占额度，`q = min(拆档量, budget)`，超额标 `targetOverflow`，余量再生成自动目标。**`plans` 只写展示字段**：改价/改量在 `merge.ts:97-106`、`suggestions.ts:216-235` 应用，不进库存、不改盈亏、不进备份的账务字段。

### 1.2 一笔买入拆成多次卖出的状态表

记卖出 `recordLotSales`（`src/store/useApp.tsx:818-853`）在事务里重读账本：校验同股、按 `lotId + targetId` 去重、`lot.remainingQty` 和 `target.qty` 足额，再按 `q = min(left, source.qty)` 逐来源生成带 `soldLotId / soldTargetId` 的子卖出记录；任一步不足整笔抛错整笔回滚。`ledger.ts:476-484` 再按 `soldLotId` 累加父批次 `soldQty`、扣 `remainingQty`。

| 阶段 | 批次字段 | 待卖 | 明细界面 |
| --- | --- | --- | --- |
| 建仓 | `qty=Q, soldQty=0, remainingQty=Q` | `SellTarget` = Q × 目标价（可拆多档） | 红边框持仓行 |
| 部分卖出 k（第 1 次） | `soldQty += k, remainingQty = Q−k` | 剩余档自动缩到 Q−k（拆档按 `at` 扣） | 仍是持仓行；已实现 = `(卖价−成本)×k` |
| 再卖出 m（第 2 次，k+m<Q） | 同上继续累加 | 继续缩量 | 同上；**没有 partial 落库标记**，状态全靠剩余量重算 |
| 卖完（k+m=Q） | `soldQty = Q, remainingQty = 0` | 待卖归零 | `isDone`（`src/domain/tradeState.ts:14-16`）= `isSoldOut && rebuyStatus !== 'pending'` → 默认「隐藏已完成」收起（链/深链/本笔待回补豁免） |

**撤销 / 删除拦截**：软删（`useApp.tsx:679-703`）、撤销（`1080-1104`）都拦策略档、合并组回执、下一轮买入、`activeDependents`（`src/domain/dependencies.ts:3-6`：子卖出引用了父批次或回补批次就不许改原行）、挂钩引用；先撤子成交，不能靠改原行清关系。有 `nextRoundOfRow` 的下一轮买入软删后额度恢复。

### 1.3 完成之后的下一轮与统计

`buyBoard.ts:74-100` 只收 `remainingQty === 0` 的真实批次（排除还没回补完的单、子卖出占用），按 C 列买入价排一档应买、基础量=建仓量；成交写 `nextRoundOfRow`（`useApp.tsx:923`）。盈利按每笔 `(售价−成本)×soldQty` 进 `totals.profitCents`（`ledger.ts:182-187、701-712`），组池 `rewardProfit.ts` 同口径；统计普通卖出只计正盈利（`statistics.ts:93-100`）。**基线红线**：62 行 fixture 盈利 797000 分 ±1 元（`defaults.ts:20-37`、`io/baseline.spec.ts:37-38`），改任何派生逻辑先跑。

## 2. 情况② 回本链：a 买 → b 卖 → c 买 → b 再卖

### 2.1 链何时成立、如何归属

`buildRepairChains`（`src/domain/chain.ts:532`）纯派生建链，不落库。两种亏损种子：

1. **真实批次高买低卖**：批次卖完出现净亏损即建链（`:150-199`），未买回也把亏损留在账上；
2. **先卖后买了结**：裸卖被高位批次挂住、回补成交后永久了结的那截亏损也建链（`:572-619`）。

归属有两条自动路径 + 一条人工路径，且**每份盈亏只归属一次**：

- **有根价位槽**：锚点后的同股、**同卖出价**裸卖自动挂回该链，按 P 列（P > 同行已确认实际回补价 > 卖出价−间隔）开槽；买入日必须不早于根卖出日（`:257-296`）。
- **无根 P 档**：锚点自己卖单的 P 列即使没有后续同价裸卖也能成槽，日期边界 = 锚点最后卖出日；同价已有有根槽则跳过；用户结束链后不再收新单（`:298-328`）。
- **人工归属** `chainLinks` / 「＋ 新增一笔归入本链」：一笔只进一条链，抢占时从旧链移出。
- **fail-closed**：日期认不出先后（null 或早于锚点最后售出日）就**不归链**（V9.56），宁可留待买单也不误把历史批次当回补。

买入按同股、价格**恰等槽价**、日期与结束边界归槽；多笔买入/卖出用 FIFO 股数份额 `slice` 分配所有权（`:330-415、643-660、747-787`），避免两条链重复认领。归属后的库存净亏保留原链，份额沿第二代实际回补继承。

### 2.2 金额与字段（务必区分「已回本」与「买回完成」）

| 字段 | 公式 / 来源 | 解释 |
| --- | --- | --- |
| `lossCents` | Σ原始亏损卖出 `profitCents` | 高买低卖的原始亏损（≤0） |
| `profitCents` | Σ分支**已实现**卖出盈利 | V9.67 起归属后任意卖价的盈亏均累计（`:468-502、856-861、909-915`） |
| `savingCents` | 有根槽 `(卖价−买价)×基础股`；无根 P 档 `(锚点清算均价−档买价)×入库股数` | **只展示，绝不进进度**；与真实盈利相加会出现「界面已回本、现金仍少 500」 |
| `netCents` | `lossCents + profitCents` | 链累计盈亏 |
| `gapCents` | `max(0, −netCents)` | 还差多少才不亏钱 |
| `done` | `netCents >= 0 && !unlinkedQty` | **链级完成 = 已不亏钱**，不是「买回数量够了」 |
| `holdingQty` | Σ分支 `remainingQty` | 已归属但尚未卖出的库存；买回未卖**不算链进度** |
| `plannedQty` | 链结束=0；有根槽=`pending + slotPending`；仅无根 P 档=`max(pending, anchorQty − 已归属买入 + 槽量)` | 还要买回的股数（`:940-975`） |

欠量统一走 `domain/cover.ts:68-94`：`owed = 卖出量 − 本行买入覆盖` → `baseQty = owed − 同价真实买入覆盖` → `openBaseQty = baseQty − 成交基础股` → 有回补价且 `openBaseQty > 0` 才有待买单。**回补成交生成的虚拟批次不参与 cover**（已在 `execQty` 扣过一次，再扣就双算）。逐笔实际回补明细由 `domain/rebuyFills.ts:7-52`（同行买入 → 成交 → 真实覆盖切片）展开。

### 2.3 「一笔数量拆多次完成」的精确判定

这是最容易写错的地方：**没有单一的「子单完成」标记**，按观察层级分别看：

| 层级 | 拆多次时的变化 | 完成判据 |
| --- | --- | --- |
| **买单 / 欠股** | 每次回补成交只消耗剩余额度；`RebuyOrder.remainingQty` 递减 | `remainingQty === 0`（且 `execQty` 累计基础股 = 欠量）→ 待买单归零、敞口关闭；奖励股不抵基础股 |
| **链的子轮次（价位槽）** | 槽里每次买入归一份份额，之后每次卖出按 FIFO 消耗份额并逐笔记盈利；分支 `cycles` = 卖出事件数/根数 | `cycles` 只回答「卖过几次」，**不是完成条件**；子轮次盈利已计入链 `profitCents` |
| **链整体** | 后续盈利逐笔累加进 `profitCents` | **唯一完成判据：`done = netCents >= 0 && !unlinkedQty`**（已不亏钱）。未买回时 `holdingQty` 只作持仓展示 |
| **统计视图（网格收益）** | 低位回本要求实际回补量 ≥ 卖出基础量；拆多次时按每笔实际买回价分别算价差 | `statistics.ts:85-92`：基础股全回补且 fills 数量/价格有效才生成 rebuy 事件，日期取最后一笔所需回补日；部分回补不计（与底仓做T不同） |

测试锚点：`src/domain/chain.spec.ts`（建链、无根 P 档、结束链、partial/多链分链）、`src/domain/regressions.spec.ts`、`e2e/accounting.mjs`。

数字算例（用户口径）：高位 10 买 500 → 7 卖 500（原始亏损 −1500）；5 买回 500，再 7 卖 500（后续盈利 +1000）→ 链净 −500，仍显示「还差 ¥500」，不是完成；若再以 5 买、8 卖赚 1500 → 净 +1000，`done=true`。**回补节省 (7−5)×500=1000 只作展示，不能把链顶成已回本**（现金并没有多出来）。

### 2.4 一个算例：10 买 7 卖 → 5 买回 → 7 再卖

高位 10 买 500 → 7 卖 500（原始亏损 −1500，链成立）；5 买回 500 → 在 7 卖这 500（后续盈利 +1000，链净 −500、`done=false`、显示「还差 ¥500」）。若要 `done=true`，还要同价买入后以更高价格卖出赚回剩余 500；**回补节省 (7−5)×500 = 1000 只展示，不能把链顶成已不亏钱**（现金并没有多出来）。若后续 5 买、8 卖再赚 1500 → 链净 +1000，`done=true`。

测试锚点：`src/domain/chain.spec.ts`（建链、无根 P 档、结束链、partial/多链分链）、`src/domain/regressions.spec.ts`、`e2e/accounting.mjs`。

## 3. 情况③ 底仓做T：从回本链单向切入，卖出量全部买回才算完成

### 3.1 入口与互斥（当前实现）

- 切入：`setSellGridMode(row, 'baseT')`（`src/store/useApp.tsx:1109-1169`）**只接受先卖后买行**（无 `soldLotId`）；写入 `grid-mode:<行>` 标记档（qty=0，strategy{mode:'baseT', sellRow, rebuyPriceCents, nextSellPriceCents, groupId}），删除原高位 hedge；待买量 = 卖出量 − 本行买入覆盖 − 已成交基础股（1142-1147）。
- 派生：`strategySales`（`src/domain/gridStrategy.ts:87-102`）按 `sellRow` 找到该标记；`src/domain/ledger.ts:75-76、586-589` 把 baseT 行从回本链自动关联中排除，`639-643` 派生 `sell.strategyMode`。
- **单向**：`setSellGridMode(row, 'repair')` 在标记档或派生模式任一为 baseT 时直接报错（`useApp.tsx:1119-1121`）；`gridStrategy.ts:69` 也禁止已有 baseT 库存迁回 repair。即使已记过部分回补也不能退回。

### 3.2 一笔卖出拆多笔子单的完成判定

| 阶段 | 派生字段 | 含义与界面 |
| --- | --- | --- |
| 未买回 | `sell.qty = Q`，`fillCount = 0`，`boughtQty = 0`，`remainingQty = Q` | 待买单挂在挂单页【应该买入】，整圈红框 `.line.base-t-buy` |
| 部分买回 k 股 @ P | `boughtQty += k`，`remainingQty = max(0, Q − boughtQty) > 0`，`profitCents += (卖价 − P) × k` | 每笔成交各算一段价差；父详情逐笔列子单，可改价/量/日期；统计日历当日 +`(卖价−P)×k` |
| 全部买回 | `boughtQty === sell.qty && remainingQty === 0` | 行卡右上角 ✅（`data-testid="base-t-done"`）、抽屉底部完成提示；hideDone 也保留该行；**不再提供左滑删除，改露「编辑」** |

`baseTRowSummary`（`src/domain/gridStrategy.ts:17-34`）是唯一汇总入口：`fillCount` = 有效回补子单数，`profitCents` = Σ(卖出价 − 子单买价) × 子单数量，`boughtQty` 含没有价格的子单（仍算数量），`remainingQty = max(0, 卖出量 − boughtQty)`。完成判定在 `src/pages/TradesPage.tsx:506-510` 用该汇总，行卡 `src/components/TradeItem.tsx:193` 只消费布尔值。

**子单如何产生/修改**：`BaseTChildModal`（`src/components/BaseTChildModal.tsx:38-76、96-115`）新建时先清残留拆档，再 `recordRebuy(..., dateIso)`；编辑走 `editRebuy(id, {qty, priceCents, dateIso})`（`useApp.tsx:936-953、966-1016`），原地改 exec 与回执，**买入日期允许晚于卖出日**，改完虚拟批次 `lot:exec:<id>` 按新值重算。

### 3.3 日历与备份

`src/domain/statistics.ts:59-82`：**每一笔回补 fill 各生成一个 baseT event**，日期落在卖出日、数量=该笔回补量、买价=该笔实际买回价、盈利=(卖出价−买价)×该笔数量；无 fill 计 pending、缺价计 unpriced。日汇总（`120-136`）累加数量/金额/盈利，另记 `baseTRebuyCount` 与 `baseTProfitCents`；日历格第三行显示**当日做T已回补盈利金额**（`StatsPage.tsx:392-394、417`）。回归锚点：`e2e/baseTChildren.mjs:217-219、268-273`（部分 +400 / 三笔 +1200 / 改日期重算）。

备份：标记档 / 子单 / hedge / chainLink / 回执整表导出恢复（`useApp.tsx:1624-1691`），`src/domain/backup.ts:141-147` 校验 mode、sellRow、qty=0、lotId 格式；`exec.at` 必须是合法时间，NaN 经 JSON 变 null 会被整包拒绝。

## 4. 三类情况的统一速查（改代码前对照）

### 4.1 完成判据不要混用

| 问题 | 正确判据 | 错误做法 |
| --- | --- | --- |
| 普通买单卖完了吗？ | `lot.remainingQty === 0` 且无 pending 回补（`tradeState.ts:14-16`） | 用 `soldQty > 0` 或「有卖出记录」当完成 |
| 回本链不亏了吗？ | `chain.done`（`netCents >= 0 && !unlinkedQty`） | 把 `savingCents` 加进 `profitCents`；把买回数量当作完成 |
| 回本链子轮次卖过几次？ | `branch.cycles`（次数统计） | 拿 `cycles` 当链完成条件 |
| 底仓做T买回完了吗？ | `baseTRowSummary.remainingQty === 0 && boughtQty === sell.qty`（`TradesPage.tsx:506-510`） | 只看 `profitCents !== null`（部分回补也有盈利） |
| 回补单还欠多少？ | `cover.ts` 的 `openBaseQty` / `RebuyOrder.remainingQty` | 把回补虚拟批次的 `remainingQty` 再扣一遍（双算） |

### 4.2 统计日历里三类的显示（2026-11-24 现行）

- **普通正盈利**：按真实卖出日，只计盈利 > 0。
- **回本链 · 低位回本**：基础股**全部**实际买回才生成事件，日期取最后一笔所需回补日，金额 = Σ(实际卖价 − 每笔实际买回价) × 各笔基础股；部分回补不计。
- **底仓做T**：每笔回补 fill 各一个事件，日期按**卖出日**，金额 = (卖价 − 该笔买价) × 该笔数量，部分回补即显示；日历格第三行显示**当日做T已回补盈利金额**（不是「回补 N 次」），并计入当日实现盈利。
- 高位原始亏损始终留在总账与链上；表现价差不再加进总账 / 链 / 奖励池。

### 4.3 改动这一类逻辑时的检查清单

1. 口径只改 `src/domain/*`（纯函数、无 IO、无 React），配单测；页面只派生消费。
2. 写库只走 `store/useApp.tsx` 的 action；拆多次成交在事务里重读额度，不足整笔回滚。
