# 版本检查与更新

更新：2026-10-29。适用于网页、添加到主屏幕的独立应用；不改变交易记账口径。

## 管理页怎么用

管理页底部显示版本卡，也可进入 **管理 → 版本与更新**。

| 显示或操作 | 含义 |
| --- | --- |
| 当前运行版本 | 这次页面实际加载的版本，来自页面构建内容，不根据线上返回值改写 |
| 线上最新版本 | 本次成功联网读取的发布版本；完整构建号相等才确认一致 |
| 上次查到的版本 | 上一次成功读取的参考信息，不能证明现在仍是最新 |
| 检查最新版本 | 绕过浏览器缓存读取固定发布信息；不会主动刷新页面 |
| 更新并刷新 | 下载并启用线上对应资源，再刷新本页；回来后核对实际运行构建号 |
| 刷新并校验 | 已是最新时也可以显式刷新，并查看“刷新完成”的校验回执 |
| 强制更新到最新版本 | 重新联网核对版本、绕过旧更新脚本缓存准备资源，并完成接管与刷新验证 |

检查显示明确时间。离线、网络失败、错误响应或发布中资源不一致时，会显示无法确认或更新未完成，不会把“没检查到”当作已经最新。可以联网后重试。

## 更新前后

先保存正在编辑的内容，再点击更新。刷新会清空尚未保存的表单和沙盒；已经保存的交易、回补成交、股票配置、凭据及操作历史保留。更新只操作应用资源，不删除IndexedDB、不清空站点数据，也不注销同域其他应用的Service Worker。

打开多个页面时，手动更新可以主动启用等待中的新版，不必反复刷新或关闭所有窗口。其他页面不会被代码强制刷新；请保存各页面内容后自行刷新。更新后的本页显示“更新成功”或“刷新完成”，并联网核对是否与当前发布一致。若刷新后仍不是目标构建号，明确提示重试，不自动循环刷新。

首次从没有此功能的旧版本升级时，旧页面自身没有新按钮。请先保存内容，关闭本站全部标签页和主屏幕窗口后重新打开一次；看到版本入口后，以后的更新直接在入口完成，不需要清理站点数据。

## 固定比较机制

每次生产构建同时生成页面内的版本信息与站点根目录的 `version.json`。构建号来自规范化源码内容的SHA-256摘要；相同源码、路径与构建模式重复构建得到相同构建号。时间、提交号仅供追溯，不用时间先后猜新旧；线上实际发布的构建号是本次更新目标，回滚发布也可正确切换。

`version.json`不进入离线预缓存。每次检查使用独立查询参数与 `cache: no-store`；响应必须符合当前应用、路径与协议。正式资源和更新脚本也携带构建身份，必须等目标资源完整安装并接管后才刷新；刷新回执再次对照页面编译内的构建号，不能仅因调用刷新成功就声称更新完成。

开发环境使用即时热更新，显示“本地开发版”，不假装检查线上生产版本。

## 维护与验证

版本构建：`scripts/buildVersion.ts`；客户端检查与接管：`src/ui/appUpdate.ts`；管理页：`src/pages/manage/ManageUpdates.tsx`。后续发布必须同时上传整个 `dist/`，包含版本文件与对应资源。

运行 `node e2e/updates.mjs`。测试会构建A、B两个真实生产包，在独立临时浏览器中保持旧标签打开，切换服务器发布后验证检查、单次更新、强制刷新、失败与离线状态，以及数据保留；覆盖 `/EzGridApp/` 子路径和320像素界面。它不操作用户平时的浏览器台账。
