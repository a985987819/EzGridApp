# 网格交易台账 · 使用手册

日常记账先查 **管理 → 成交流水**，确认未记过再保存。新增、补买入、挂单成交与回补均检查相似事实；一次合并成交保留一个编号、多份来源分配。步骤与限制见[成交记录与核对](成交记录与核对.md)。

> 这份手册解释系统里**每一种明细、每一种情况**：它怎么产生、在界面哪里看到、数字怎么算、你该做什么。
> 想查精确公式和历史决策看 `AGENTS.md`；想按数据类型速查看 `docs/detail-kinds.md`；上手看这一篇就够。
>
> **30 秒上手**：管理页导入 Excel（或手动新增）→ 明细页看持仓 → 挂单页填昨收点确认 →
> 按三组（应该买入 / 锦上添花 / 应该卖出）挂单 → 成交后点「记成交 / 记卖出」→ 台账自动算一切。

**安装到桌面**：管理首页顶部点「安装应用」。支持的浏览器会打开安装窗口；其它情况可展开当前设备的添加步骤。更换浏览器或使用部分独立应用时，本地数据可能不共用，可先点「备份台账」导出，安装后核对并按需恢复。详见[安装与版本更新](版本检查与更新.md#安装应用)。

---

> **现行说明（2026-11-04）**：先卖后买默认采用「低位回本」，按日期识别，回补价按 P 列 > 同行已确认实际回补价 > 卖出价减间隔；自动关联同股、卖出时已买入的高位未占用批次。显式「底仓做T」、人工关联和「解除并停止自动关联」继续优先。已归属库存之后任意卖价的实际盈亏均应按份额归原链，回补节省不算盈利。移动端在管理 → 操作指南可查[按情况处理步骤](操作指南.md)；当前已知偏差见[操作边界与核对](操作边界与核对.md)，不要把规则说明当作所有组合均已实现。

## 一、先建立大局观：一笔交易的「一生」

台账的核心是**一行记录 = 一笔买入或卖出**。系统从它自动派生出所有其它对象：

```
Excel / 手动录入
   └─ 一行记录（records）
        ├─ 买入侧有数据 → 买入批次（Lot）→ 批次有剩余 → 待卖档（挂单页红色「应该卖出」）
        │       └─ 卖出后 → 卖出成交（盈利落袋）
        │            └─ 有 P 列（回补价）→ 待买订单 → 记成交 → 虚拟批次（又一个待卖档）
        └─ 只有卖出侧 → 先卖后买（裸卖）→ 敞口 + 待买单（挂单页「应该买入」）
```

你**永远只操作两样东西**：录入数据、确认成交。批次、待卖、盈利、链、统计全部自动派生，不落库、可随时重算。

**行号段位**（识别一行的来源）：Excel 导入行用 Excel 行号；手动新增从 100000 起；
回补生成的虚拟批次从 200000 起；沙盒模拟从 300000 起（纯内存预览）。界面统一叫「第 N 笔」（按录入时间排序，Excel 行号只出现在追溯信息里）。

## 二、明细页：所有类型逐个讲

明细页每行左边有**状态色条**：红 = 有东西要卖，蓝 = 有东西要买，无色 = 已完成。
每行可以点开抽屉看详情、编辑、拆分、挂钩。

**查找与筛选（2026-11-04）**：从合并挂单点击整行或「查看 N 笔来源」，明细会同时列出全部实际来源；单独点击某笔来源仍只看该笔。顶部「限定 N 笔来源」可点 × 移除一笔，或「取消来源限定」继续查看当前股票的其它记录。回补虚拟批次没有独立明细行，会定位到生成它的原卖出记录；同一记录的重复拆档只列一次。

「按第几笔查找」可填 `2、5、8-10`，点「应用序号」后查看第2、5、8、9、10笔；这里的数字是界面序号，不是Excel行号。该操作替换原来的来源限定，其它股票/状态/价格/日期条件继续生效。明确指定的已完成或软删除记录也会显示；不存在的序号不会匹配其它记录。输入有误时会提示并保留原筛选，一次最多选5000笔。

展开「价格与日期筛选」可设最低/最高价及起止日期，留空表示不限、边界包含。价格在买入价、卖出价、目标价、回补价中任意一个命中即可；日期优先取卖出日，缺失时取买入日，两者都缺失的行在日期筛选中排除。不同筛选条件同时满足才显示，多状态也取交集；结果为空时可逐个移除条件或「清空筛选」。清除序号仅移除序号条件；筛选保存在链接中，支持刷新和浏览器返回，不改变账务。

### 2.1 常规先买后卖——最普通的一轮

**怎么产生**：一行同时填了买入侧（日期/买入价/份额）和卖出侧（卖出价、卖出日期、实现份数）。

| 阶段 | 界面表现 | 数字 |
| --- | --- | --- |
| **持仓中**（买 700 股，还没卖） | 红色边框行，显示「目标价 × 剩余」 | 待卖档 = 剩余份额 × 目标价；预期盈利 = (目标价 − 买入价) × 剩余 |
| **部分卖出**（卖了 300） | 仍是持仓行 | 已实现 = 已卖部分；待卖 = 剩余 400 × 目标价 |
| **全部卖出** | 变「已完成」，默认被「隐藏已完成」开关收起 | 盈利落袋 = (卖价 − 买入价) × 股数 |

**点行打开抽屉**可以：编辑允许修改的字段、补买入（先卖后买专用，见 2.5）、拆分止盈（2.2）、人工合并关联（2.3）。已录入的买入/卖出份额在普通编辑中只读；有后续依赖时关键字段还会被限制。

### 2.2 拆分止盈：一个批次、多个卖价

批次卖不到一个价？抽屉里「卖出目标」区可把剩余份额拆成多档：比如 700 股，10.00 卖 300、10.50 卖 400。
- 股数默认「还能拆的量」，价格默认 E 列目标价（没填就按买入价 + 间隔推）——**留空点「拆分」即可**。
- 手动目标先占份额，剩下的仍挂在 E 列价上；拆多了自动按剩余量夹住。
- 挂单页【应该卖出】按拆出的档分列；删除某档即恢复。

### 2.3 同价合并显示（V9.45）

**批量连续拆档与双模式（2026-11-02）**：挂单页「连续拆档与策略」可把多笔尚未被占用的份额连续排档，例如两笔1000股生成四个500股档，相邻价差0.30元；单独设置每轮回补价差。「低位回本」的低位循环实际盈亏归原链；「底仓做T」实际买回多少就以真实成本批次恢复多少原高位卖量，策略价差单列。策略台账提供再拆剩余和未成交档撤销。步骤及已回补/多高位来源等限制见[拆档与先卖后买双模式](拆档与先卖后买双模式规划.md)。策略卖档保留独立身份，不跨模式同价合并。

几笔**同股、最终挂单卖价相同、都没卖完**的批次，在挂单页【应该卖出】会自动**并成一行**（数量相加、日期取最早），即使买入成本不同也可汇总。行上标「合并 N 笔」，展开/跳转查来源。这只是显示合并，明细和成本仍按原始批次保存；人工同买入价合并组是另一层可选关系。

### 2.4 卖光之后：下一轮应买 vs P 列再买

批次卖光后它去哪，取决于 P 列（提前卖的买价）：

| 情况 | 结果 | 出现位置 |
| --- | --- | --- |
| **没填 P 列** | 变「下一轮应买」档：股价回到买入价那一档就提醒再买一轮，基础量 = 建仓量，可加同池未授奖励 | 挂单页【锦上添花】，行标「下一轮」 |
| **填了 P 列** | 变一张待买订单（回补再买入），按 P 价挂着 | 挂单页【锦上添花】，行标「P 列再买」 |
| 部分卖出 + P 列 | 待卖（剩余部分）和 P 列再买（已卖部分）**并行** | 各在各组 |

注意 P 列的双义：**先买后卖**行填 P = 下一轮想买回的价（锦上添花）；**先卖后买**行填 P = 必须买回的价（应该买入）。

### 2.5 先卖后买（一）：裸卖与敞口

**怎么产生**：一行**只有卖出侧**（买入价、日期、份额全空），或者卖出日期 ≤ 买入日期（A 股 T+1，同日也算先卖后买）。

这表示你卖了「当前还没买的股」——**空头敞口**：
- 行标「先卖后买」+ 橙色「待回补」；挂单页【应该买入】出现一张待买单（回补价 × 尚欠量）。
- 概览的「待补敞口」= 所有未买回的空头股数；守恒式「Σ待卖 − 敞口 − 回补基础股 = 净持仓」保证账不平就亮灯。
- **时间确认后的回补按份额闭环**：本行后来补的买入直接算回补本身（买多少抵多少），只剩差额挂单。
- 卖出日期留空/是 `=TODAY()` 公式没有缓存值 → 无法判序，保守地保留整张待买单（fail-closed）。

### 2.6 先卖后买（二）：挂钩——把亏损先挂在账上

先卖后买默认采用「低位回本」，按卖出时间关联当时已买入、价格最高且尚有未占用份额的同股高位批次。明确选择「底仓做T」的记录继续按该模式处理，人工关联和解除覆盖保留。可点「已挂钩 · 改挂」调整；未找到高位时点「裸卖待挂钩」人工指定，已回补也能调整原始成本。选择「解除并停止自动关联」后不再自动挂回。

- 挂住的份额退出待卖、按（卖价 − 买价）**暂记负盈利**；裸卖自身盈利暂缓。
- 面板默认只列高位买单（挂上去才亏），有「自动挂满」「允许挂不满」「显示全部」开关；
  每行输入框占位「≤可挂量」，留空 = 不挂。
- 一直不买回 → 暂记负盈利就是真实亏损。
- 买回一部分 → 买回那截**永久了结**（批次不复活，亏损留在合计盈利里），剩下继续挂；撤销成交自动回到挂住状态。

### 2.7 先卖后买（三）：拆开买回

一张大卖单想在多个价位分批买回？抽屉「买入拆分」区按价位拆成多档（如 5.00 买 300、4.50 买 200）：
- 价格默认 P 列（派生不出按卖价 − 间隔），股数默认「还能拆的量」——留空点确认即可。
- 挂单页【应该买入】按档分列，来源明细标「第 N 档」；未拆部分保留默认回补价，新成交按来源档扣量（改成交价不改来源），旧成交按价格匹配。
- 已落库的份额只读（防止改历史），只能改对手价；删除某档后已成交份额自动回落到其它档。

### 2.8 回补成交与虚拟批次

在待买单上点「记成交」（填本次股数/成交价/奖励股数，都有默认值）：
- 系统**自动生成一个虚拟批次**（买入价 = 成交价，目标价 = 成交价 + 间隔），回到【应该卖出】——网格自动进入下一轮。
- 虚拟批次明细页没有行；想改它的价格/日期只能撤销成交重记。
- 敞口按成交股数减少；买满后待买单关闭、状态变「已回补完」，批次转入下一轮提醒。
- 「记成交」连点有防重保护；奖励股数填 0 表示本次不买奖励股。

### 2.9 组池奖励：用赚到的钱送自己一手

明细列表和抽屉会显示**当前价位累计盈利**：同一股票、同一实际买入成本价的可奖励净盈利汇成组池，同时列出「已买奖励占用」「剩余可用」及可再买股数。

**回本链先补亏**：未完成或高位成本待关联时，链内份额暂不计入；人工结束不代表已经回本。完成后只计扣掉原始亏损的净超额，补亏用过的盈利不再奖励，回补节省也不算盈利。若一条链包含多个实际成本价位，净超额按各价位后续正净贡献分配，合计严格等于该链净超额。普通独立交易的亏损仍抵减对应价位的普通盈利。

**每够一手加100股，多手可以全加**。例如5元买500股、7元卖出，累计盈利1000元；可再买200股，下一轮推荐为基础500＋奖励200＝700股。原待回补订单与下一轮共用一份余额，先满足待回补订单已分配的奖励，再把余量给下一轮；同价合并不会重复领取。推荐仍受已确认日内区间和最低未完成买入成本限制，缺少有效买入候选时不凭空新建订单。

已买奖励按**实际买价×奖励股数**占用原价组预算，不把这笔占用再扣一次总账盈利。部分成交优先分配全行基础股，再买100股整手奖励；基础买完后，未用奖励可保留为尾量。5元累计1000元时，先买600股会记500基础＋100奖励，占用500元、还剩500元；继续买奖励尾量100股后余额归0，刷新、备份恢复不会重复发放。基础来源只扣500，实际库存仍按全部700股保存。

改单提高价格会按最终价缩减奖励；写库再按实际成交价和同组全部来源累计检查预算，不足则整笔拒绝。计划降低价格不会放大原已分配奖励。历史已买奖励在后来亏损、改数或链重新未回本时仍保留，预算不足亮检查且停止新增；撤销整笔仍受后续依赖限制。升级新奖励口径后，请刷新其它已打开的本站页面再继续记账。

### 2.10 记卖出子成交（V9.57）

任何批次（包括回补的虚拟批次）卖出后，还可以对**别的批次**记卖出：抽屉里指定来源即可。父批次被占用后，改关键字段/删除/撤销都会被拦，先处理子卖出——保证账不乱。

## 三、挂单页：每天开盘前看这一页

**第一步永远是填昨收价并点「确认」**——系统按涨跌幅档位算出今日区间 [跌停, 涨停]，所有档位按区间内外分拣。

各买入分组按价格**从高到低**排列，卖单按价格**从低到高**排列；以改单后的最终挂单价为准。区间外列表、沙盒、复制清单和挂单 CSV 使用相同顺序，底部逐笔回补台账按回补价从高到低排列。

**买入推荐范围（2026-11-02）**：页面先展示「上次最低未完成买单」，取当前股票仍有未卖份额的最低实际买入成本，含回补批次。若该价为7.71，则应该买入与锦上添花只推荐**严格低于7.71**、同时位于昨收涨跌幅区间内的现有档位；7.71本身也排除。若昨收8.00、涨跌幅10%，日内区间7.20–8.80，则今日买入推荐范围为7.20–7.70。下一档参考价按最低成本减股票间隔计算（如7.71−0.57=7.14），只是参考，不自动新增挂单。

未确认昨收/涨跌幅时不出今日买入推荐；交集为空就提示没有符合范围，不提高上限凑档位。无未完成持仓时不猜参考价，只按日内区间筛选。卖光最低批次或新买更低价后参考会重算，切股只取当前股票。沙盒取预览库存；复制与挂单CSV只列今日符合条件的买入。筛选不影响原欠股、库存、奖励和回本链，完整原始回补记录仍可在台账中核对。

已改单的价格被上限筛掉后，可在参考卡的「改单未纳入推荐 · 调整计划」里调低或清除；此处只有计划管理，不提供高价成交入口。

### 3.1 应该买入（红标）

先卖后买的待回补单——**卖出拿回来的钱就欠着这些股**。行上标「先卖后买」，可能带「敞口」「回本链」标；金额合计与「组池可分配」在卡片头部/脚部。

### 3.2 锦上添花（蓝标）

不是欠账、是机会：
- **下一轮**：已完成批次回到买入价那一档，再买一轮。
- **P 列再买**：先买后卖行填了 P 的待回补单。
- **下一轮与P列待买共用价位盈利余额**：先满足原待回补订单，再把未授余额分给下一轮；基础股与奖励分别显示、不能重复领取。点来源可跳明细，也可记录真实成交。

### 3.3 应该卖出（橙标）

所有批次的未卖份额（含拆分档），同价自动合并，行带预期盈利；底部合计。

### 3.4 越界与区间外

区间外的档**今天无法成交**，折叠成一行「区间外 · N 档 · X 股（价 x~y）」；点开有完整行，可以改单把价位拉回区间内。买入侧此处只保留低于最低未完成买单的候选，同价或更高价不列入；今日复制/CSV不输出这些区间外买入。

### 3.5 台账折叠区（默认收起）

底部「台账 · 逐笔回补 N 条」是审计工具：每张待买单的计划量/组池/已回补进度、**撤销最后一笔成交**、裸卖待挂钩入口。日常用三组就够了，翻账才展开。

### 3.6 改单

每行「改单」按钮改**这一条的显示价量**（计划价量）：影响今日区间判断、导出、记成交默认值——**从不回写原始记录、不动盈亏**。把两条待买改到同价会自动合并成一条（来源分开保留）。

每条推荐买单、卖单下方以小字显示「原推荐 x 股 · 金额」，指不应用改单时，该档当前剩余份额对应的推荐金额和数量。它不是历史成交总量；部分成交后随剩余量重算。改单撞价合并时按各原档的原价、原量累计，买单的欠股回补、可选再买和策略模式继续隔离。拆档按各档当前原推荐计算，不重复累计整张母单；沙盒和区间外列表采用相同对照。实际挂单、复制/CSV及记成交默认仍使用当前显示的改单价量。

### 3.7 沙盒

右上「沙盒」开关：加模拟待买/待卖、模拟挂钩，看「已实现盈利/理想可卖到」会怎么变——**纯内存预览**，刷新即清空；每行「记为成交」才真正写库。

## 四、回本链：亏掉的钱怎么赚回来

每笔先卖后买都显示链；关联高位后按高买低卖确定原始亏损。没有高位成本时显示待关联。普通高买低卖净亏损也保留建链。链卡四个数字：

| 数字 | 含义 |
| --- | --- |
| 原始亏损 | 按当前原始成交与高位关联计算的亏损；不会因买得便宜自动减少，改挂/修正历史会重算 |
| 后续净盈利 | **归属于这条链**的后续买卖已实现盈利——低位买回后每次卖出的利润都往这里累加 |
| 链累计盈亏 | 两者相加；≥0 显示【已不亏钱】 |
| 回本估算 | 剩余 x 次可以回本；按下方注明的买卖价差和每次股数估算 |

**剩余次数（2026-11-04）**：`向上取整（尚未弥补亏损 ÷ 每轮参考盈利）`，一轮统一按这条链原亏损对应的股数计算；卡片注明参考买价、卖价、股数及每轮盈利。优先采用最近一笔归属低位盈利成交的实际价差；没有时参考归属低位库存的原卖出目标，再没有时参考原先卖单的回补计划，并标明计划口径。例如10元买500股、7元卖亏1500元，按5买7卖、每轮500股可赚1000元，初始估计2次；已完成一轮后还差500元，显示「剩余1次可以回本」。不把买回节省提前抵亏，不把多代回补历史股数相加；缺高位成本或没有正价差时暂不估算，已回本显示「已不亏钱」。次数只作同价差、同股数重复的参考，未扣费用；总账、回本链实际盈亏不变。

**归属规则**（哪些交易算进这条链）：
1. **锚点 P 档**：P 列对应的回补价位——之后**直接记成交买回、明细新增、下一轮买入**的批次自动归档，它们的卖出盈利逐笔累加（V9.63）。
2. **同价再卖**：链之后同股、同卖出价的裸卖自动挂链，按各自 P 列开档。
3. **人工指定**：锚点抽屉里可把同股其它批次勾进链（一笔只进一条链）；「＋ 新增一笔归入本链」也行。
4. **你点「结束这条链」后**：历史和已有归属保留，新库存停止自动归链；已有库存后来卖出仍累计。「重新打开」可恢复。实际回补有精确时间时按结束时刻判断；只有日期的历史批次仍按日期边界处理，无法猜测同日先后，见[操作边界与核对](操作边界与核对.md)。

**两条铁律**：「卖 7 买 5 省下的钱」只展示不计入进度（防止界面说回本了、现金却没到）；买回没卖出的部分只算持仓。链锚点/成员行**不被「隐藏已完成」挡住**——欠着账的链随时可见。

## 五、统计页：了解网格做到哪了

- **网格进行度**：完成轮次（买入后已卖光）、进行中批次、**每轮均盈**、平均持仓天数、待卖/待回补/敞口、最热价位。
- **高成交点位**：按（股票 × 买入价）排名——完成次数最多的档，条形图对比，点行跳明细。
- **网格收益日历、年/月累计、月度列表与趋势**：统一使用独立的网格收益视图。普通先买后卖只计实际正盈利，在卖出日显示；高买低卖的原始亏损留在总账和回本链，不在这组收益展示中抵减。
- **先卖后买的收益确认**：整张订单的基础股全部实际买回后，才一次展示 `Σ（实际卖价 − 实际买回价）× 配对基础股数`，归到最后一笔所需基础股买回的日期。未回补、部分回补都不计；奖励股不能代替基础股，计划回补价也不作为收益依据。
- **后续低位循环**：买回的实际库存后来盈利卖出，仍在那次卖出日计普通网格盈利；明确引用库存来源的子卖出不再当作新的先卖单。
- **按股票 / 组池 / 账务汇总**：继续展示真实总账和奖励池。日历等处的网格收益只说明交易表现，不加进总账、回本链或奖励池，也不能与这些数字重复相加。
- **日期与次数**：未知收益确认日期单列，不占趋势中的有效月份；高位成本分配的合成卖出不增加真实成交次数。价格树与按批次计算的进行度、每轮均盈仍须按各自口径核对，不能当作本轮网格收益视图。

例如先以7元卖500股，后来5元买回200股、5.5元再买回300股：首笔买回后日历不计收益；全部买回当天一次显示850元。原高位10元成本形成的−1500元仍留总账和回本链；低位库存未再卖出前，链进度不因这850元表现值而增加。

### 概览中的个股筹码分布

概览切换股票后，在该股价格树下方可见「筹码分布」，只统计本地台账中当前股票：

- **成交最高频次范围为**：在不超过该股一个网格间隔的价格跨度内，找全部历史实际买卖笔数最多的区间。一次合并成交分配到多个来源只算一笔；历史同一行的买入和卖出各算一笔，实际回补也算买入。界面显示买/卖笔数、累计成交股数，以及占有效成交的比例。缺少明确价格、混价或数量无效的事实单独提示未纳入；日期未知仍可计入全部历史。
- **大量未完成买单范围**：按实际买入成本，找同样最大跨度内仍未卖出股数最多的区间。仅使用当前批次剩余份额，含回补批次；部分卖出后只算剩余部分，拆挂单或改单不重复增加库存。界面显示剩余股数、批次数与占本股有效剩余库存的比例。「大量」表示本股剩余筹码最集中的范围。

例如间隔0.50元，5.00与5.20元的4笔成交可集中为5.00–5.20；9.00与9.20元的剩余1400股可集中为9.00–9.20。5.00、5.40、5.80不能连锁并成跨度0.80元的一段。未配置有效间隔时只比较同价；区间端点取实际存在的价格。并列时成交依次比较成交股数、较窄跨度、较低价；库存依次比较批次数、较窄跨度、较低价。

展开「查看价位分布」可按低到高查看各实际价位的成交次数与剩余股数，两列条形分别对照各自最大值。初次显示10档，之后每次再看最多20档。点数字或「查看来源」会用全部真实来源定位明细，回补批次定位到原卖出记录。沙盒开启且有模拟项目时，两项按同源预览重算并标「含模拟」，混有未落库来源的整组不跳转；刷新后恢复真实统计。所有统计都只展示，不改变库存、盈亏、奖励或备份。

## 六、管理页：模板 / 导入 / 校验 / 备份

- **下载 Excel 模板**：标准【交易记录】表头 + 填写说明表，给任何人填完导入。
- **导入**：普通 xlsx（只读第一个工作表）/ csv；预览按身份匹配新增或更新卖出侧，匹配不明确时先选择来源。有效交易行中的非法股数、日期或超范围金额会按原文件行号、字段和原因列出，整批修正后再导入，不自动取整或跳过错误行。股数字段允许空值、0或非负安全整数；实际成交使用真实整数股数，不强制为100的倍数。普通XLSX按工作簿的1900/1904日期系统解释数值日期，文本日期不重复位移。已有后续成交的行有修改限制；回滚前备份并核对来源依赖。
- **导出**：明细页「完整台账 Excel（可恢复）」导出全部数据和关联；「明细 Excel/CSV（查看）」仅供分析，带用途标记，不可恢复导入。新增数据使用空白模板。详见 [完整台账 Excel](完整台账Excel.md)。
- **校验**：基准体检 + 数量守恒式，红灯按提示处理。
- **完整台账 Excel**：管理 → 备份中导出所有交易、成交、配置、人工关联和回本链核对快照；重新导入会先预览与重算核对，再整库替换。排序不影响关联，自动关联仍自动生成。详见 [完整台账 Excel](完整台账Excel.md)。
- **备份**：导出全量 JSON（恢复前自动先导快照）；长期不打开浏览器可能清理 IndexedDB，**每周导出一次备份**。

当前结构14的JSON与完整Excel会检查必需表、计算设置、记录字段和关系；旧版按兼容步骤迁移后校验。导出读取同一时点的原始数据和计算设置；相同新版本的其它窗口提交后会自动更新。管理页清空交易记录使用一个完整事务，失败时保留原业务数据，股票配置继续保留。沙盒关联转正的模拟买入、卖出与挂钩也整体保存，任一失败保留原模拟项目供重试；页面打不开时还可从异常提示直接备份，见[页面恢复](版本检查与更新.md#页面暂时无法打开)。

## 七、数字口径速查

| 数字 | 怎么算 |
| --- | --- |
| 待卖档 | 批次剩余 × E 列目标价（拆分档各自算）；缺目标价按买入价 + 间隔推导 |
| 已实现盈利 | Σ(卖价 − 成本) × 卖出股数；挂钩暂记的负盈利也算在内 |
| 待卖预期盈利 | (目标价 − 买入价) × 剩余——计划中的钱，不是已实现 |
| 敞口 | 裸卖未买回的股数；挂住的份额已由高位批次交割，不算 |
| 守恒式 | Σ待卖 − 待补敞口 − 空头回补基础股 = 净持仓（= Σ买入 − Σ卖出） |
| 组池容量 | floor((组内盈利 − 已用) / 每手成本) |
| 链累计 | 原始亏损 + 归属的后续已实现净盈利；节省只展示 |
| 网格收益展示 | 普通实际正盈利＋整单基础股实际回补完成的先卖后买价差；独立表现视图，不回填总账/链/奖励 |
| 每轮均盈 | 完成批次自身的盈利 ÷ 完成轮次（统计页口径，不含裸卖） |

**精度**：正常范围内以整数分运算；价格换算、导入股数、实际价量乘积及真实买卖现金/股数累计会检查有限安全整数。超范围输入需修正，历史异常记录不会被自动改数；全部派生指标与底层数值组合尚未穷尽验证。固定 fixture 的金额容差不等于任意数据都容许差额。

## 八、常见疑问 FAQ

**Q1 为什么链卡亏损一直不变？**
先查后续买入的来源、日期与回补档，确认库存是否归属本链。已归属库存后来任意卖价的实际盈亏都应入链；仅买回未卖出不算盈利。原始亏损不会因回补节省自动减少，改挂/修正原始数据则会重算；自动亏损脱链、多轮断链等边界见[操作边界与核对](操作边界与核对.md)。

**Q2 为什么我的待买单自动消失了？**
先查本行实际买入、独立真实买入覆盖和回补成交的基础股是否已补满。奖励是额外库存，不应代替基础欠股闭环；挂单价量缩小或筛选也可能让某行暂时不可见。展开逐笔回补台账并核对来源，避免重复录入。

**Q3 先卖后买的卖出日期比买入日期早，是错的吗？**
这是本台账识别先卖后买的日期规则；同日也按先卖后买处理，不是对真实交易权限或证券规则的判断。保留真实日期，时间确认后按实际份额覆盖，未知日期不猜已回补。

**Q4 明细里有些行看不见了？**
「隐藏已完成」开着——卖光的批次收起来了。回本链的锚点/成员不受影响；点其它页跳转过来的行也会自动显示。

**Q5 改单会改坏数据吗？**
未成交的改单不改变真实账务，清除改单恢复派生建议。合并缩量和成员来源分配仍有边界，保存后需重读数量；实际记成交会改变库存与盈亏。部分计划/拆分/配置动作目前缺完整操作审计，不能只靠日志判断有没有修改。

**Q6 数据会丢吗？**
全在本机 IndexedDB。长期不打开可能被浏览器清理——每周导出备份兜底；换设备用备份文件迁移。

**Q7 导入提示「悬空引用被拒」？**
老备份里挂钩/拆分指向已不存在的行——系统宁可拒绝也不静默丢账；先用能对上的数据导入。

## 十、边界与已知取舍（设计如此，不是 bug）

- 虚拟批次不能行内编辑——改价/日期撤销成交重记即可。
- 超卖（卖出 > 批次）会标异常并亮守恒式红灯——按提示补数据。
- 沙盒纯内存：刷新/恢复备份/清库即清空。
- 自动归属先按同股、来源、买入价位和日期寻找；归属确定之后任意卖价的实际盈亏均应按份额累计。当前偏差单列在[操作边界与核对](操作边界与核对.md)，不能当作设计如此。
- 金额与 Excel 基准 ±1 元容差（三位小数取整）。
