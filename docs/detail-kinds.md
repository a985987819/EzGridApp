# 明细类型图鉴

> 想一步步上手（含操作指引与 FAQ）看 `docs/使用手册.md`；本篇是按数据类型的速查图鉴。
> 给「看台账的人」和「接手的 agent」：台账里每一笔数据是什么、怎么判定、在界面上显示成什么、
> 进哪些账。公式与历史决策以 `AGENTS.md`「关键口径」表为准，本文是它的分类导读。
> 文中「挂单页三组」指 V9.58 起的布局：【应该买入】【锦上添花】【应该卖出】+ 底部「台账」折叠区。

> **当前口径（2026-10-27）**：先卖后买按日期统一识别，回补价按 P 列 > 同行实际回补价 > 卖出价减间隔；默认按时间关联最高价未卖高位批次。所有先卖单都有链，后续同价已完成买卖累计实际回本，关联明细共享完整链。详见 [先卖后买与回本链](先卖后买与回本链需求.md)，本说明优先于下文旧版操作记录。

## 0. 一行数据的身份系统（先读这个）

`records` 表的一行 = 一笔原始交易。每行同时有四个身份：

| 身份 | 含义 | 备注 |
| --- | --- | --- |
| `sourceRow` | 主键 | Excel 导入行 = Excel 行号；行号撞车时分配未占用号，原行号存 `excelRow`（V9.49） |
| 行号段位 | 来源类型 | Excel 行 1~99999 · **手动行 100000+** · **回补批次虚拟行 200000+**（不是 record，见 §3）· **沙盒模拟 300000+**（纯内存，见 §6） |
| `importKey` | 内容幂等键 | 同 key 再次导入只更新卖出侧字段（V9.20 决策 C） |
| `nanoId` / `recordNo` | 跳转 id / 「第 N 笔」 | 跨页跳转用 nanoId；序号按录入批次时间纯派生（V9.43），软删行仍占号 |

**一行 records 最多派生出三个可见对象**：买入批次（Lot）→ 待卖档（SellTarget）→ 卖出成交（SellExecution）→
若欠回补再派生待买订单（RebuyOrder）。下面按类型展开。

## 1. 常规先买后卖（网格的基本轮次）

**判定**：行同时有买入侧（C 列价 + 份额）和卖出侧，买入日期早于卖出日期。

**生命周期与去向**：

| 阶段 | 判定 | 界面 | 账务 |
| --- | --- | --- | --- |
| 持仓中 | 批次 `remainingQty > 0` | 明细行红色待卖边框；挂单页【应该卖出】一档 = 剩余 × E | 待卖预期盈利单独算，不进已实现 |
| 部分卖出 | 卖了一部分、还有剩余 | 仍是持仓行 | 已实现 = 已卖部分；待卖 = 剩余部分 |
| 已卖光 | `remainingQty === 0` | 明细「已完成」，默认被「隐藏已完成」收起（回本链锚点/成员豁免） | 已实现盈利落袋 |
| 卖光后没填 P 列 | 无 open 待买单 | **下一轮应买档**（V9.47）：挂单页【锦上添花】，价 = C 列买入价、量 = 建仓量 | 纯提醒，不进任何合计 |
| 卖光后填了 P 列 | 待回补单 open | **P 列再买**待回补（非 sellFirst）→【锦上添花】 | 进待买剩余金额、组池 |
| 部分卖出 + P 列 | 两者并存 | 待卖（剩余部分）与 P 列再买（已卖部分）**并行两行** | 各算各的 |

**衍生形态**：

- **拆卖 `extraTargets`（V6）**：一张批次的待卖按价位拆成多档（`et:<lotId>:<ts>`），待卖按档显示、
  分开挂单；拆分上限 = 批次剩余，超额自动夹住（V9.51）。**拆的是卖出的价位，不动批次本身**。
- **同价合并组 `merges`（V9.45）**：多笔**同股、同买入价、未卖完**的批次在挂单页并成一行（数量相加、
  日期取最早、`data-merge-group` 跳最早一笔）。**纯展示**：明细、守恒式、价格树都按原始批次算；
  卖到只剩一笔自动散开但关联保留。不同买入成本的批次按**卖价**自动汇总（V9.49 起）。

**优化评估**：拆卖/合并的入口都在明细抽屉，挂单页行上只有改单——高频用户若想「行内拆」可以加，
目前频度不值得。深链跳明细时若之前停在页面下方且筛选已收起，落点看不到筛选区（见 §8）。

## 2. 先卖后买（卖出发生在买入之前）

**判定**（`ledger.ts` 的 `sellBeforeBuy` + V9.47.1）：①无买入批次的**裸卖**（买入价空）；或
②有卖出日且买入日空，或卖出日 ≤ 买入日（A 股 T+1 当日买的不能当日卖，**同日也算**）。确认先后后按股数闭环：
`ownLotCoverQty = min(批次量, 卖出量)`，本行后来补的买入就是回补本身（决策 G）。

**状态机**：

| 状态 | 判定 | 挂单页 | 敞口 |
| --- | --- | --- | --- |
| 未回补 | 欠量 > 0 | 【应该买入】待买单（`sellFirst`），红「空头敞口」标 | 全额 |
| 部分回补 | 有成交、还剩欠量 | 同上，量 = 差额 | 差额 |
| 已回补完 | `remainingQty === 0` | 买单关闭；买回批次完整留在【应该卖出】 | 归零 |
| 挂钩了结 | 记了回补成交且挂着高位批次 | 买回那截**永久了结**（V9.36）：被挂份额不复活、亏损留在合计盈利里 | 已交割部分不算 |

统一减法在 `domain/cover.ts`（V9.57）：`owed → baseQty → openBaseQty → openExposureQty`，
真实同价买入覆盖、回补成交、挂钩各扣一次，**杜绝双算**（守恒式 R7 的输入）。

**衍生形态**：

- **挂钩 `hedges`（V9.26，决策 E）**：先卖单默认按时间关联最高价剩余高位批次，亦可**人工指定**挂到同股未卖的高位批次（合计 = 卖出量）。
  挂住：被挂份额退出待卖、按（卖价 − 买价）暂记负盈利，裸卖自身盈利暂缓；一直不买回 = 暂记
  负盈利即真实亏损。撤销成交回到挂住状态；人工解除存空覆盖，防止自动再挂回。挂错行/超挂/挂不满都标异常。
- **价位槽（V9.49，决策 H）**：链之后同股**同卖出价**的裸卖自动挂回那条链、按 P 列开槽；之后所有
  同股同价的买入（回补成交/明细新增/导入）自动进槽累计盈亏。日期认不出先后就**不归链**（V9.56 fail-closed）。
  **锚点 P 档（V9.63）**：锚点自己卖单的回补价（P 列）即使没有后续同价裸卖也是一档——亏损建链后
  **直接记成交买回 / 明细新增 / 下一轮买入**的批次都自动归档，它们的多次卖出盈利逐笔累加进链
  （修复「亏损固定显示、低位盈利不相加」）；用户结束链后不再归。
- **拆买 `buyTargets`（V9.50）**：一张先卖后买单按价位拆成多档买入（`buytarget:<卖单行>:<ts>`，
  展示档 `rb:sell:<行>#<N>`）。成交按价格落档（V9.51.1），总量受「卖出量 − 本行买入」约束。
  **已落库的买入/卖出份额只读，只能改对手价**（改单锁）。
- **记卖出子成交（V9.57）**：对真实/回补批次再记卖出（`soldLotId`），父批次被占用后关键编辑、
  删除、撤销都要先处理子卖出（`dependencies.ts` 拦截）。

**优化评估**：挂钩已有「一键自动挂满/允许挂不满」，流程闭环；拆买入口在明细抽屉的卖单行，
挂单页只能整档改单——同 §1，暂不加行内拆分。**P 列语义提示**：先买后卖行填 P 列 = 下一轮再买价
（会出现在【锦上添花】），先卖后买行填 P 列 = 必须回补的价（【应该买入】）——同一列两种含义，导入时留意。

## 3. 回补成交与虚拟批次（R6，V9.20 决策 B）

- **记回补成交**（`exec:<orderId>:<ts>`）→ 自动生成**虚拟批次** `lot:exec:*`（目标价 = 成交价 + 该股间隔）
  回到待卖清单。虚拟批次**不落库**：明细页没有对应行、不能行内编辑，撤销成交即消失。
- 已回补完的订单保留为 `closed`（历史与组池奖励 `doneRewardQty` 还看得见）。
- 想改虚拟批次的买入日期/价格 → 只能撤销成交重记（已知取舍，低频保留）。

**优化评估**：无（撤销重记的代价可接受，自动建批次带来的待卖闭环价值更大）。

## 4. 组池奖励（R4/R5）

- 组池 key = `股票|成本分`（V9.32 起单一账户）；gross = 组内全部真实卖出盈利；
  容量 = floor((gross − used) / 每手成本)；**FIFO** 授给最早还能买的单。
- 奖励股随回补成交一起买入（`validateExecutionInput` 要求整手、不超额度），**已成交不可撤**。
- 校验「Σ已买回的奖励手数 ≤ Σ组容量」：挂钩/改数把池子缩水到装不下已买回奖励时亮黄灯（V9.33）。
- 界面：待买行「含奖励 N」、【应该买入】卡脚「组池可分配 ¥x」、统计页组池明细。

**优化评估**：无。

## 5. 回本链（V9.46 主口径 + V9.49 价位槽）

- **建链时机**：每笔先卖后买都显示链，成本不明标待关联；普通已卖份额出现净亏损当场建链（含部分卖出、尚未回补的挂钩亏损），无须等清仓。
- **累计口径**：链累计 = 原始亏损 + **归属于它的后续买卖已实现净盈利**；**回补节省只展示不计入**
  （决策 F：两条一起算会出现「界面已回本、现金仍少 500」）；买回未卖 = 持仓不算进度。
- **归属**：价位槽自动（同股同价）+ `chainLinks` 人工指定（一笔只进一条链）+ 用户「结束/重开」
  （`closedAt`，结束后的新交易不再自动归链）。每份盈亏只归属一次，全局已实现盈利不重复加。
- **界面**：概览链卡（四数字 + 进度条 + 分支列表）、明细行 `data-chain` 标签、`hideDone` 豁免。

**优化评估**：人工归属与自动槽并存，出现冲突时人工优先；数据里暂无错归案例，不动。

## 6. 沙盒（V9.39）

- 「模拟待买」（先卖后买预演）/「模拟待卖」（假设买入），行号 300000+，**纯内存**：
  刷新/恢复备份/清库即清空，不进备份、不写审计、不进明细。
- 模拟行可挂真实/模拟批次（预演亏损）、可「记为成交」转正成真实手动行（连同挂住的模拟批次一起转正）。
- 挂单页三组在沙盒下照常工作（数据切预览账本），「＋ 模拟待买/待卖」在沙盒面板里。

**优化评估**：无。

## 7. 界面落点速查

| 数据类型 | 明细页 | 挂单页 | 概览/统计 |
| --- | --- | --- | --- |
| 持仓批次（未卖完） | 红边框行 | 【应该卖出】档 | 可卖/净持仓/价格树待卖枝 |
| 已完成批次 | 「已完成」（默认隐藏） | 【锦上添花】下一轮档（`data-buy-level`） | 树上灰枝 |
| 先卖后买未回补 | 蓝边框 + 待回补/敞口标 | 【应该买入】待买单 | 待补敞口、守恒式 |
| 先卖后买已回补 | 已回补完 + 回本链 | 订单关闭；回补持仓在【应该卖出】 | — |
| 挂钩 | 抽屉挂钩面板 / `HedgeSheet` | 台账折叠区入口标签 | 链卡、暂记负盈利 |
| 回补批次（虚拟） | 无行（记成交弹窗里看） | 待卖档（「回补批次」标签） | 树上正常出现 |
| P 列再买 | 行上 P 列 | 【锦上添花】「P 列再买」标 | — |
| 回本链 | `data-chain` 标签 | 台账区回本链标 | 链卡（未结束未回本的） |
| 沙盒模拟 | 不可见 | 紫虚线行 | 沙盒横幅、树重画 |

## 8. 2026-10-27 审计记录

核对范围：`cover.ts` 统一覆盖模型、`buildBuySplits` 拆分档截断与按价落档、`mergeTargetRows`
计划链与组预算、`splitBuySuggestions` 三组切分（含沙盒）、越界折叠、明细页收放动画、`scrollHold`
钉屏。**未发现新的阻断性问题**；守恒式检查、组池校验、备份外键校验均有单测/e2e 钉住。

三个小观察（非 bug，留作后续清理）：

1. `domain/buyBoard.ts` 合并行里有两段等价的 `anchorRow` 更新逻辑（先 `<` 后 `<=` 各一次），
   可以合并成一段——行为一致，纯冗余。
2. 跨页深链（价格树/统计跳明细）不重置滚动位置：若之前停在页面下方且筛选区已收起，落点看不到
   已生效的筛选 chips（V9.47 只豁免了 hideDone 隐藏）。可优化为「带筛选深链时滚回顶部」。
3. 沙盒模式下【锦上添花】的下一轮档沿用 `levelLine` 渲染（没有记成交按钮），与真实模式（建议行
   可直接记成交）不一致——刻意保留：沙盒的「记为成交」走转正路径，两者入口不同不冲突。

## 完整台账 Excel 的关联表示（2026-10-27）

人工高位挂钩、回本链成员、批次合并使用父表 + 成员表，以固定记录 ID 引用。自动高位关联与链成员放在 `核对_` 表中，只作快照展示，恢复时由同一领域引擎重算；回补虚拟批次由原成交 ID 重建，不重复导入记录。格式、空关联与恢复规则见 [完整台账 Excel](完整台账Excel.md)。
