# 操作指南：遇到这种情况怎么办

更新：2026-10-29。管理 → **操作指南**可搜索本文、108 个核对场景和完整文档；指南随应用保存，应用资源缓存完成后可离线阅读。

这里的操作基于当前台账规则。文中“应有结果”是核对标准，已发现的实现偏差单独指向[操作边界与核对](操作边界与核对.md)，不能把说明当作缺陷已经修复。

**日常顺序**：先查管理 → 成交流水是否已经记过 → 核对真实成交与本次来源分配 → 保存一次 → 按成交编号与凭据核对。相似记录会提示；核实是另一笔才确认新增。详细流程见[成交记录与核对](成交记录与核对.md)。

## 开始使用与录入

### 01 第一次使用，应该从哪里开始？

1. 管理 → 股票设置，确认股票名称、默认间隔和涨跌幅配置。
2. 在管理 → 导入数据下载空白 Excel 模板；已有数据先保存副本，再选择 Excel 或 CSV。
3. 看预览的新增、更新、冲突及数量，确认后写入本地。也可在明细页手动新增真实买入或卖出。
4. 去明细核对持仓，再到挂单页选择股票、填写昨收并确认。
5. 交易真实发生后才记成交；最后到管理 → 备份导出完整台账。

**核对**：股票、股数、实际日期与成交价应与原始记录一致；未发生的目标价不是实际利润。

### 02 Excel、CSV、完整台账和 JSON 分别用在什么地方？

- 空白模板、普通 Excel/CSV：录入新增或更新交易，先看导入预览。
- 完整台账 Excel：完整备份、换设备或调整关系，恢复前预览，确认后整库替换。
- 明细 Excel/CSV：导出当前筛选供查看，不含完整关联，不能当完整备份导回。
- JSON：程序备份；使用本程序导出的完整文件，不要手写空对象或删表后恢复。

**注意**：普通模板按“元”填写价格；完整台账原始表按“整数分”保存，8.01 元对应 801。详见[完整台账 Excel](完整台账Excel.md)。

### 03 重复导入或只更新几笔，怎样避免改错记录？

1. 先导出完整备份，保留未修改原件。
2. 在导入预览中逐笔查看“新增 / 更新 / 冲突”，尤其留意只有卖出侧的记录。
3. 对照股票、买入信息、卖出价量及日期，再确认写入。

**当前边界**：裸卖子集重导可能误匹配已有另一笔；不要仅凭“重复导入”提示就认为绝对幂等。涉及这类记录时先暂停确认，见[导入身份风险](操作边界与核对.md#d01)。

### 04 第 N 笔、Excel 行号和完整台账记录 ID 为什么不同？

“第 N 笔”按录入顺序显示，删除的记录仍占序号；Excel 行号只用于追溯原表；完整台账的记录 ID 用于保持关联。它们本来就不是同一个数字。

**操作**：查找交易优先用界面的第 N 笔和日期；编辑完整台账时保留记录 ID、成交 ID、关联 ID 与“原始顺序（勿改）”，不要按排序后的物理行号重编。

### 05 日期、股数或价格缺失，应该怎么填？

1. 以真实成交凭据补齐日期和价格，不猜测已经买回。
2. 股数使用正整数；价格使用正常范围的正数，不填无限长数字或小数股数。
3. 导入时把 TODAY 等公式转成确定值，确认日期没有被自动进位。
4. 普通 Excel 建议使用 1900 日期系统；1904 日期文件应先转换并核对日期。

**注意**：未知日期会保守保留待买，缺价格可能不生成可执行档位；这不表示欠股已经清零。非法日期、1904 日期制和极端数值仍有已知边界，见[操作边界与核对](操作边界与核对.md)。

## 日常挂单与真实成交

### 06 每天挂单前要核对哪些数字？

1. 退出沙盒，选择今天要操作的股票。
2. 填写昨收并点确认，检查跌停、涨停；手工调整后再核对。
3. 分清应该买入、锦上添花、应该卖出，展开来源核对每笔股数。
4. 检查是否“已改单”，成交默认值可能不同于原始建议。
5. 用券商真实成交更新台账，再核对剩余股数；不要把台账建议当作已向券商下单。

**顺序**：买价由高到低，卖价由低到高，以最终改单价为准。台账不连接券商，也不自动获取行情。

### 07 应该买入与锦上添花有什么区别？

应该买入对应先卖后买尚欠的股份；锦上添花对应已卖批次的下一轮机会，或先买后卖记录中填写的 P 列再买。两组资金目的不同。

**应有结果**：欠 500 股、可选买 300 股，即使同价也应分开，不能把 800 股都当作欠股。

**当前边界**：同价或改单撞价仍可能跨组混合。看到一条建议同时有“先卖后买”和“下一轮 / P 列再买”来源时，先按来源拆开核对，勿直接按整行当欠量成交，见[买入目的混合](操作边界与核对.md#o02)。

### 08 持仓只卖出一部分，怎么记录？

1. 在挂单 → 应该卖出找到对应档位，展开或跳明细核对来源。
2. 点记卖出，填写本次实际价格、日期和股数；股数可以小于当前挂单量。
3. 保存后检查该批次剩余量；不同实际成交价可分次记录。

**算例**：买入 700 股，本次卖 300，剩余应为 400；本次盈亏只按 300 股结算。不要新增一笔不带来源的裸卖代替卖出这批库存。

### 09 待买只买回一部分，怎么记录？

1. 找到对应买入档，核对股票、卖出来源与档位。
2. 点记成交，填写真实买回股数、成交价与日期；如无奖励，奖励数量填 0。
3. 保存后核对“基础股已回补”和剩余欠量；新买回库存会进入应该卖出。

**算例**：欠 500 股，本次买回基础股 200，仍欠 300；买回这 200 股自身仍是新的持仓。不要又在明细新增同一笔买入，否则会重复记账。

### 10 一笔想拆成几个买价或卖价，怎么做？

在挂单行的拆分入口，或明细抽屉的“卖出目标 / 买入拆分”中设置档位。未拆的剩余量继续留在默认价格；拆分只改变计划分档，不改变真实成交与持仓总量。

**核对**：所有档位合计不超过真实剩余；成交后检查原档扣量。新成交保存来源档，实际成交价改变不应误扣另一档。

**当前边界**：合并建议分别缩量后再成交，可能按原来源量扣错档。此类组合先逐档记成交并核对余量，见[来源贡献量](操作边界与核对.md#o04)。

### 11 同价合并会改变原来的交易吗？

卖单按同股票、最终挂单卖价合并，买入成本不同也可以显示成一行；原始交易和成本仍分别保存。买单同价合并还必须保持业务目的隔离，当前该隔离有已知问题。

**操作**：合并行先展开来源。一次实际成交会按来源顺序分配，若需要指定某笔或某档，先进入对应来源操作；不要把显示合并当成原记录合并。

### 12 改单会改变盈亏吗？清除后会怎样？

改单改变该建议的显示价量、区间判断、复制导出和成交默认值；未实际成交之前不改变原始持仓或真实盈亏。清除改单应恢复派生建议。

**当前边界**：合并成员数大于填写的总量时，系统可能将总量静默放大；多个成员各自缩量也可能保留过大的来源贡献。保存后重读整行数量与来源，不能只看成功提示，见[合并计划数量](操作边界与核对.md#o05)。

### 13 区间外为什么不能直接记成交？

当前涨跌停区间外的档位折叠在“区间外”摘要中。先核对昨收与涨跌幅配置；确认是计划价格问题时，可改单拉回区间。

**注意**：不要为了让按钮可点就随意改区间。记录历史成交应核对真实交易日和价格；当天区间提示不能替代历史成交凭据。

### 14 沙盒、记成交和记为成交有什么区别？

- 沙盒中的模拟条目只是预演，不写入真实台账；刷新会丢掉模拟内容。
- 真实建议的记成交 / 记卖出记录实际发生的交易。
- 模拟条目的记为成交将模拟转为真实记录，点击前要确认已经发生。

**当前边界**：开启空沙盒时，真实建议级改单可能不显示。真账已改单后，应退出沙盒再核对价格和数量，见[沙盒显示计划](操作边界与核对.md#o06)。

## 先卖后买与高位关联

### 15 什么情况会识别成先卖后买？

卖出日期早于或等于买入日期、没有买入价或只有卖出日期等情况，会按先卖后买识别。明确指定买入批次的子卖出按来源核算，不重复当作裸卖。

这是台账的识别规则；不要为了消除标记，把真实日期改成另一日。日期未知时，系统不会猜测已经回补。

### 16 本行补买入、另录买入、记回补成交，应该选哪一个？

同一笔真实买入只能记一次：

1. 原行本来就代表这笔先卖后买的完整记录，可在原行补买入。
2. 已有独立真实买入记录时，先核对它是否已经覆盖欠量，不要再点一次回补成交。
3. 尚未录入的真实回补，可在对应待买档记成交。

**核对**：同一买回份额只覆盖一次，同时保留其实际库存。未知日期或买价不匹配时，先查归属，不要用重复买入消除提示。

上述入口统一检查相似真实成交；已经记过就查看原成交。已有记录无法自动覆盖时暂不支持任意重新指定回补来源，不要再记一笔解决显示问题。

### 17 为什么还欠股，敞口却是 0？

“待回补基础股”和“空头敞口”不是同一个数。已挂到高位库存的卖出份额已有库存交割，敞口可能为 0，但仍有计划买回的数量。

**操作**：同时看逐笔回补台账、对应高位批次与实际持仓；不要仅因为敞口为 0 就认定已经买回。

### 18 高位关联是怎么选的？如何改挂或解除？

系统先尊重人工关联，再按卖出时间寻找当时已买入、有可用份额、成本高于卖价的同股真实批次，优先高价批次。

点明细或台账的“已挂钩 · 改挂 / 裸卖待挂钩”核对并调整。选择“解除并停止自动关联”会留下人工空覆盖。

**恢复自动选择**：先保留完整台账原件，在副本中删除该笔“人工高位关联”的父行及对应“人工高位分配”子行，再从完整 Excel 恢复预览核对。只清空分配、保留父行仍表示禁止自动关联；不确定关联 ID 时不要直接删表，先查[完整台账 Excel](完整台账Excel.md)。

**核对**：同一份高位库存不能分给两笔卖出；没有可关联成本时应显示待关联，不能当作已回本。

### 19 回补后，高位批次会重新变成待卖吗？

不会。买回的基础股对应的高位交割份额永久了结，原亏损留在账上；新买回的低位批次成为新的持仓。部分买回时只了结对应份额。

撤销回补会重新派生之前的状态，但必须先核对子卖出、拆分档及历史引用，不能为“让旧批次回来”重复新增库存。

## 回本链怎么核对

### 20 买得更便宜，为什么还没有回本？

链累计盈亏 = 原始亏损 + 归属后续交易的已实现净盈利。买回尚未卖出，只增加持仓；卖出到买回的节省只作参考，不抵亏损。

**算例**：10 元买 500 股，7 元卖出，原亏 1500；5 元买回未卖，后续盈利仍 0。后来 7 元卖出这 500 股赚 1000，链仍亏 500。

### 21 后续卖价不是最初那个价，还能算回本吗？

能。归属已经确定的库存，后来任意实际卖价产生的利润或亏损，都应按归属份额累计到原链；卖价不是结算过滤条件。

**当前边界**：自动归属的低位真实库存自身出现净亏损时，可能脱离原链。应核对原链剩余库存与负盈亏；只有该真实批次确实完整属于一条链时，才可用人工归属明确关系。多链分摊不能盲目把整批移给一条链，也不要另录一笔盈利“补数字”。见[自动归属亏损](操作边界与核对.md#c01)。

### 22 买回又卖出，再买第二轮，链为什么少了库存或盈利？

多轮库存与实际盈亏应沿来源延续，每份只计一次。

**当前边界**：自动槽的第二代回补可能断链；全局持仓与总盈利正确，也不代表链卡正确。先保留备份，逐轮核对买入来源、子卖出、回补成交及链持仓，不要重复记成交补链卡。见[多轮回补断链](操作边界与核对.md#c02)。

### 23 怎么手动指定一笔交易归入回本链？

打开链锚点的明细抽屉，展开人工归属，选择同股票真实批次并保存；也可使用“新增一笔归入本链”录入尚未记录的真实买入。

**核对**：已存在的买入应直接选择，不能为归链再新增一遍。一笔只能归一条人工链，改归后检查旧链和新链的库存、盈亏。

### 24 结束、重新打开和已回本分别是什么意思？

- 结束：保留已有历史与归属，阻止结束后新库存自动加入；原库存后来卖出仍应更新原链。
- 重新打开：恢复接收新交易的资格，历史仍在。
- 已回本：当前累计不再亏损，不代表人为结束；后续归属库存亏损仍可能重新变负。

**当前边界**：自动路径可能把结束时刻之后的同日回补收入旧链。结束当天要逐笔核对真实时刻与归属，不要改成交日期绕过问题，见[同日结束边界](操作边界与核对.md#c03)。

### 25 计划回补 5 元，实际买在 5.50，应该看哪个成本？

真实成本以 5.50 元成交为准；P 列 5 元只是计划档位。后续实际盈利按真实成本计算。

**当前边界**：链分支可能仍用计划价展示买价和参考节省。例如 7 元卖、5.50 买 500 股，实际节省 750 元，不是按 P5 算的 1000 元。核对实际成交与批次成本，见[计划价与实际成本](操作边界与核对.md#c04)。

## 奖励与统计

### 26 奖励一手是多少股？可以不买奖励吗？

一手为 100 股。奖励按同股票、同成本价组的真实卖出盈利预算计算，满足一手成本才有可分配额度；已完成订单不会再领取新奖励。

记回补时可把本次奖励设为 0。已成交奖励是实际库存，不能因预算后来缩小就自动删掉；撤销整笔成交需要满足其依赖限制。

**区分**：下一轮提醒不参与奖励；P 列待买订单可能带奖励，以该订单基础股与奖励明细为准。

### 27 实际买价提高，奖励仍然全部由利润支付吗？

不一定。实际奖励支出 = 实际成交价 × 奖励股数；成交价上涨后，原计划奖励股数可能超过利润预算。

**算例**：利润 1000 元，按 5 元可支付 200 股奖励；实际 10 元买 200 股需 2000 元。

**当前边界**：系统可能先接受股数、事后才报预算不足。录入前核对实际金额；已经真实发生的成交保留真实价量，资金缺口另行核对，不能编造成交价消掉红灯。见[奖励超预算](操作边界与核对.md#o03)。

### 28 日历或价格树的成交次数，为什么和实际交易不一样？

高位关联会生成成本分配视角，它不是第二次真实成交。

**当前边界**：日历和价格树可能把这类合成记录再次计入数量与次数，统计完成轮次的说明也有不一致。先对照原始卖出和明细，不能把展示的双倍数量当成券商多成交了一次。总账与链、统计均应分别核对，见[统计口径](操作边界与核对.md#v01)。

### 29 缺日期的盈利为什么不在想看的月份？

统计依赖真实卖出日期。未知日期不能随意摊入某个月；当前趋势图还可能出现空标签并占用月份位置。

**操作**：有凭据时补真实日期；没有凭据则保留未知，单独核对相关成交，不能改成今天只为让图表好看。

## 改错、撤销与删除

### 30 已成交的数量填错了，能直接编辑吗？

已录入的买入 / 卖出份额在普通编辑中只读；不要通过改单修改历史数量。改单只改建议。

**操作**：先备份，查看该笔有无子卖出、回补或下一轮依赖。需要重记时从依赖末端处理，保留真实成交依据；不要绕过页面限制直接改备份主键。

### 31 明细里找不到原来那笔，是丢了吗？

先清空筛选，检查股票、日期、价格条件，再关闭“隐藏已完成”；需要时打开“显示已删除”。软删除仍保留序号。

回补生成的虚拟批次没有独立原始明细行，应从挂单中的回补批次和逐笔回补台账查来源。沙盒模拟本来就不进真实明细。

### 32 回补已经卖出，为什么不允许撤销？

后续子卖出引用了这笔回补库存，先删来源会让成本和持仓失去依据，因此会被拦截。

**当前边界**：按提示软删子卖出后再撤销回补，历史记录仍可能留下悬空引用；带拆卖档的回补撤销也可能残留档位。涉及这些组合时先保存完整备份、记录依赖，暂停继续撤销并核对恢复可用性，见[撤销后的历史关系](操作边界与核对.md#d04)。

### 33 软删除、撤销成交、回滚导入有什么区别？

- 软删除：暂时移出某笔原始记录，保留历史和序号，可恢复；有占用时可能被拦截。
- 撤销成交：移除选中的回补成交，对应虚拟批次消失，欠量按规则恢复。
- 回滚导入：移除该导入批次及可识别关联，并不是撤销之后所有业务。

**当前边界**：原批次已经用于下一轮买入时，回滚可能漏掉来源依赖。不要把回滚当成任意时刻的整库时光机，见[回滚依赖](操作边界与核对.md#d03)。

### 34 想恢复已删除交易，怎样避免超卖或重复买入？

先检查其原批次是否已经被其它交易占用、下一轮来源是否已被使用，再恢复。恢复失败时阅读提示，不要通过复制一笔相同交易绕过额度限制。

恢复后同时核对持仓、待买、后续子成交和关联链；已有依赖的历史交易不能只看一行是否重新出现。

## 备份、迁移与异常

### 35 换手机、换浏览器或清缓存前，怎样迁移？

1. 在原设备管理 → 备份导出完整台账 Excel，另存一份 JSON 备份。
2. 将文件保存到浏览器之外，确认文件确实下载成功。
3. 在新设备打开同一应用，从完整 Excel 恢复，先核对预览，再确认整库替换。
4. 对照原设备的记录数、真实成交、盈利、持仓、待买及重要回本链。
5. 重新核对昨收与手工区间；沙盒和页面偏好不属于完整台账内容。

恢复验证前不要清掉原设备数据。不同设备、浏览器和站点的数据不会自动同步。

### 36 完整台账恢复出现差异，还能确认吗？

先下载重算核对表，区分修改了原始数据、修改了人工关系，还是引擎规则变化。`核对_` 表只是旧快照，改它不能改变真实账务。

能解释的差异才确认；不能解释时取消，保留原库和原文件继续核对。确认是整库替换，不是追加导入；恢复前自动快照也需要确认已成功保存。

### 37 JSON 缺表、只剩部分内容，还能恢复吗？

不要恢复手工删表的部分文件。缺交易记录表的JSON会拒绝；重复主键、主要金额/股数非法及来源循环也会拒绝。旧格式的可缺省表仍按兼容规则处理，不能把部分JSON当成局部合并工具。

**处理**：优先使用未手改的完整导出文件；保留当前完整备份，在副本中确认缺失内容。空对象 `{}` 不是“清空台账”或完整恢复的安全替代，见[JSON 恢复边界](操作边界与核对.md#d06)。

### 38 备份提示悬空引用，应该怎样处理？

这表示成交、拆分或人工关系引用的来源找不到。不要只删掉报错字段强行导入，可能会丢掉真实成本或历史关系。

**处理**：保留当前库与原始备份，记下报错表、记录 ID 和关联来源；优先寻找最近一份未出现问题的完整备份，在副本中逐级核对。已知撤销 / 回滚组合可能生成这类状态，见[操作边界与核对](操作边界与核对.md)。

### 39 管理页校验全绿，就能说明所有账都正确吗？

不能。基准快照是固定样本参照，用户自己的交易不应强行改成样本数值；数量守恒只检查已定义的数量关系。

**核对顺序**：原始交易 → 真实成交 → 来源与分档 → 剩余库存 / 欠股 → 回本链归属 → 盈亏与奖励预算 → 备份可恢复。总股数相等也可能存在错档、混组、漏归链或历史引用问题。

### 40 出现红灯，应该从哪里查？

先备份并保留原始成交凭据。看红灯对应股票、记录和差额：缺价补真实价或配置；超卖查来源与重复成交；奖励不足查实际成交金额；关联异常查可用库存与人工分配。

暂时无法解释时停止追加纠错操作，记下操作顺序、具体数字和备份。不要编造买入、卖出或改真实日期把红灯“调绿”。

### 41 离线能不能看指南？本地数据会自动同步吗？

应用完整加载、离线资源缓存完成后，指南与台账可在本机离线使用；首次从未加载过应用时仍需要联网。指南无需登录或读取外部文档。

数据只在当前浏览器保存，不跨设备自动同步。清理站点数据、浏览器存储回收或换浏览器都可能失去本地台账；定期导出并在浏览器外保存备份。

### 42 提示有新版本，普通刷新却没变化怎么办？

先保存当前编辑，不要清理站点数据，以免连台账一起删除。

管理 → 版本与更新，查看当前运行版与线上最新版本，点“检查最新版本”。有新版就点“更新并刷新”；仍未切换时点“强制更新到最新版本”。刷新回来会明确显示校验结果。离线或检查失败时不能确认最新，联网后重试。

更新只处理应用资源，已保存台账保留；尚未保存的表单及沙盒会随刷新清空，先保存再更新。首次从没有此入口的旧版升级，先保存、关闭本站全部窗口后重开一次。完整说明见[版本检查与更新](版本检查与更新.md)。
