# 交易、拆单与导出审计修复记录

本次保持现有回本链口径，修复此前审计确认的七项问题，并补齐连续操作回归。

| 问题 | 修复结果 |
| --- | --- |
| 同订单多档合并成交重复使用基础回补额度 | 事务内累计各来源的基础股和奖励股；奖励档先成交也不占用其它档基础股；合并挂单的按钮进入多来源成交 |
| 卖档成交后旧档重新出现 | 子卖出保存来源档身份，按来源扣量；改单不丢来源，部分成交只扣实际量，撤销恢复原档 |
| 部分拆买把未拆份额移到最后一档 | 未拆基础股单列默认价；基础股与奖励股分开分配，新成交保存稳定来源身份 |
| 子卖出卖光后父买入仍未完成 | 完成和已卖完判断集中到 domain；父批次卖光完成，子明细保留自己的待回补状态，回本链显示豁免继续生效 |
| CSV 不识别“已卖”，缺列清空旧字段 | 兼容旧 CSV 的“已卖 / 成交价”；增量导入缺列保留原字段，显式空单元格仍可清空 |
| 普通明细 Excel 不能恢复子成交及关联 | 明细页优先提供全量完整台账导出；筛选明细标明仅供查看并拦截导入；完整台账保存新增的成交来源档身份 |
| 显示与成交校验的推定售价开关不一致 | 事务重建账本采用相同设置，页面显示的基础股及奖励额度可以正常成交 |

另外修正奖励预算检查：已成交奖励应以实际金额和成交时所属价组，比较该组累计盈利；原来拿已使用奖励与剩余容量比较，会在预算正常用完时误报。新增按订单检查，拦出基础成交超过基础回补量的历史异常。

完整 Excel 计算口径版本升为 2，兼容版本 1；JSON 仍为 schemaVersion 11，可选来源字段无需数据库迁移。旧成交缺失的改单前来源无法准确反推，仍按同价兼容匹配；旧完整文件按新口径重算，恢复前显示差异。不会自动改写历史成交中的基础股、奖励股或来源身份，历史错误需核对后撤销重记。

验证覆盖真实 CSV 的 62 笔数据、部分买卖、同批次多档、改价、撤销、奖励档优先成交、完整 Excel 往返后继续操作，以及相关明细打开同一回本链。单测 368 条、真实 IndexedDB 账务浏览器回归 64 项、页面冒烟 477 项全部通过；Lint 与生产构建通过。
